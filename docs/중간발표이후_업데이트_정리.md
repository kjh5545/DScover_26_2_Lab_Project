## 2. 인선 — 판정 프롬프트 비교 실험 (완료)

### 무엇을 했나
- 모델과 입력은 그대로 두고 **판정 프롬프트만 바꿔서** 각각 3번씩 돌렸어요.

  | 조건 | 내용 |
  |---|---|
  | p0 | 규칙 없음 |
  | p1 | 사전 실험 규칙 |
  | p2 | + 팀 결정 (수동 스크리닝) |
  | v3 | 지금 쓰는 프롬프트 |
  | v3_r1112 | + 보류한 규칙 11·12 |
  | control | AI가 직접 쓴 규칙 (해준) |

- 1차(10/28~10/30): 평가 세트 + 기존 상세 환자 S004·S008 → **규칙을 만들 때 본 데이터(개발 세트)**
- 2차(11/04): **새 상세 환자 4명 독립 검증** → 프롬프트를 확정한 뒤 한 번만 돌림
- 비용: 1차 약 $2.3, 2차 약 $1.76

### 결과 1: 평가 세트 (개발 세트, /173)
| p0 | p1 | p2 | v3 | v3_r1112 | control |
|---|---|---|---|---|---|
| 140 | 149.7 | 169 | 170 | 170.7 | 149 |

→ 규칙을 더할수록 올라갔어요. 특히 **p1 → p2(팀 결정)**에서 크게 뛰었어요. p2 이후 차이는 1~2개라 의미 없어요.

### 결과 2: 새 4명 독립 검증 (/142) ⭐
| 조건 | 정답 v1 | 정답 v2 | 등록 후 확인 (/26) |
|---|---|---|---|
| p0 | 119.3 | 114.3 | 14.3 |
| p1 | 118 | 115 | 13.7 |
| **p2** | **125.3** | 126.3 | 20 |
| v3 | 122.7 | 127.7 | 20.3 |
| v3_r1112 | 121.3 | **128.3** | 20.3 |
| control | 120.7 | 118.3 | 14.3 |

쉽게 말하면 이래요.
- **어느 정답으로 봐도 같은 것 (믿을 만함)**
  - p2 이후 조건이 p0·p1·control보다 높아요.
  - "등록 후 확인" 구분은 p2 이후 20/26, 나머지는 14/26 안팎이에요.
  - 규칙을 더할수록 AI가 조심스러워져요. "모름인데 통과" 실수는 줄고(25 → 2), "통과인데 모름" 실수는 늘어요(5 → 35).
- **정답에 따라 뒤집히는 것 (말하면 안 됨)**
  - p2·v3·v3_r1112 순서예요. v1에서는 p2가 1등, v2에서는 v3_r1112가 1등이고 차이는 1~3개뿐이에요.

### 인선님이 요청한 정답 확인 → 11/06 처리 완료
- 팀 단체 채팅방에서 규칙을 먼저 정하고, 6명 시트 전체에 똑같이 적용했어요.
- 결과: 정답 7칸 변경. 고친 칸 대부분이 AI 답과 같은 방향이라, v2 점수는 AI에 유리할 수밖에 없어요.
- 정답 규칙 중 하나가 판정 규칙 11과 내용이 같아요. 그래서 v2에서 v3_r1112가 오른 건 "정답을 규칙 11에 맞춘 효과"가 섞여 있어요.

## 3. 해준 — 대조군, 검색 개선, 데모, 규칙 11·12 제안

### 3-1. 대조군(control): "수동 스크리닝 없이 AI가 규칙을 쓰면?" (11/04, 병합됨)
- AI에게 과제와 판정 정의만 주고 규칙을 직접 쓰게 했어요. 우리 규칙이나 데이터는 안 보여 줬어요. (생성 $0.03, 실행 $0.86)
- 결과: **AI가 쓴 규칙은 "규칙 없음"(p0)과 비슷하고 팀 결정(p2)보다 낮아요.**
- 결정적 차이는 **"등록 후 확인" 구분**(control 14 vs p2 20, /26)이에요. "어디까지 물어볼 수 있는 정보인가"는 팀이 회의로 정한 기준이라 AI 혼자 못 만들었어요. → **수동 스크리닝 효과의 가장 좋은 근거.**
- ⚠️ 해준님 커밋 메시지의 상세 환자 숫자(/188)는 S004·S008(개발 세트)과 새 4명을 합친 값이에요. 독립 검증으로 말할 때는 새 4명만(/142) 써야 해요.

### 3-2. 검색 개선 (실험 3, 11/06 병합: PR #5·#7)
| 바꾼 것 | 이유 |
|---|---|
| 검색어 1~3개 → 5~8개 (진단명 구체→일반, 동의어, 증상) | 검색어가 안 맞아서 놓친 시험이 있었음 |
| 검색어당 시험 50 → 200건 | 페이지 한도 때문에 정답 3건을 놓쳤음 |
| AI(Haiku)가 관련도 0~100점 매겨 정렬, "진료 단계" 고려 | 확진 환자용 치료 시험이 진단 단계 환자의 정답을 밀어냈음 (S004 정답 109위 → 4위) |

| 지표 (골드셋 15개) | 개선 전 | 개선 후 |
|---|---|---|
| 정답이 검색 풀에 있음 | 67% | **93%** |
| 정답이 상위 5개 안 | 40% | **53%** |
| 정답이 상위 30개 안 | 60% (랭킹 없이) | **87%** |

- 기본값도 바뀌었어요: **랭킹 켬, 기본 후보 3 → 5개, 데모 슬라이더 최대 10개.** 비용은 랭킹 환자당 약 $0.12 추가, 스크리닝 비용은 후보 수만큼 약 1.7배.
- ⚠️ 랭킹 규칙을 같은 15개를 보면서 만들었으니 이 숫자는 **개발 세트 성적**이에요. 발표 때 "개발 세트 기준"이라고 붙여야 해요.
- S008 미스(149위) 분석: 그 시험은 "급성 악화 환자 전용"이라 진단 전 환자에게 순위가 낮은 게 맞아요. 버그 아님, 한계로 기록.

### 3-3. 데모 개선 (11/06 병합: PR #4·#10·#11, S004 번들)
- **미리보기 선택 (PR #4):** 저장된 결과 파일을 골라서 API 없이 데모 화면에 띄울 수 있어요. (전에는 S005 하나만 가능) 목록에 N001·N002도 뜨는 건 서현님이 괜찮다고 확인했어요.
- **S004 리허설 번들:** `S004_리허설_10-18`을 고르면 10/18 리허설 장면(질문 5개, 답변, 바뀐 판정)이 API 없이 재현돼요. 발표 시연 백업용이에요.
- **멈춤 버그 수정 (PR #10):** AI가 JSON 뒤에 설명 문장을 붙이면 데모 전체가 멈췄어요. 읽기에 실패했을 때만 앞쪽 JSON만 다시 읽게 고쳤어요.
- **랭킹 병렬화 (PR #11):** 관련도 채점 묶음을 동시에 5개씩 돌려서 랭킹 구간 93초 → 17초.
- 데모 한 명: 약 2.7분 → **약 1.5분**, 약 $0.3

### 3-4. 규칙 11·12 채택 제안 (PR #9) → 11/06 회의에서 보류
- **제안 내용:** 실제 판정 프롬프트(`src/agents/matcher.py`)에 규칙 11·12를 넣자는 것. 비교 실험의 v3_r1112 조건과 같아요.
  - 규칙 11: 특정 진단 기준(ATS/ERS 등)을 요구하면 "진단받았다"만으로는 모름
  - 규칙 12: 진단 X가 있다고 다른 병이 없다고 볼 수 없음 → 모름
- **장점:** 3회 실행 간 흔들림이 가장 적고, 실수 방향이 "통과→모름"이라 위험이 작아요.
- **보류 이유**
  1. 1등이 되는 건 정답 v2에서뿐이에요. 고치기 전 정답(v1)의 독립 검증에서는 p2보다 낮았어요(121.3 vs 125.3).
  2. AI가 더 조심스러워져서 "통과인데 모름" 실수가 늘어요. 모름이 늘면 질문 부담이 커지는데, 질문은 한 번에 5개까지예요.
  3. 서현님 질문 실험이 지금 프롬프트(v3)를 기준으로 하고 있어서, 바꾸면 실험과 데모가 서로 다른 시스템이 돼요.
- 다시 검토하려면 새 환자로 독립 검증을 한 번 더 해야 해요.
