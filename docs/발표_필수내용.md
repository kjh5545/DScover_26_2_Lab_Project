# 중간발표에 꼭 들어가야 할 내용 (10/24)

> PPT 제작·발표: 인선·서현 · 정리: 주희
> 장 수와 디자인은 자유예요. 다만 **아래 A~F는 빠짐없이 들어가야 해요.** 우리 팀이 한 일의 중심이 A(수동 스크리닝에서 시작한 판정 개발)와 B(에이전트별 개발)라서, 이 둘이 발표의 절반 정도를 차지하면 좋겠어요.
> 숫자·예시·출처는 `docs/발표자료_중간발표.md`에 더 자세히 있어요. 이 문서는 "무엇을 꼭 말해야 하는지"를 정리한 거예요.

## 발표 흐름 (이 순서로 이야기가 이어지게)

```
문제 → A. 수동 스크리닝으로 판정 규칙을 찾고 → 프롬프트로 옮겨 실험 → 자동 평가로 모델 선택
     → 사람이 만든 정답(평가 세트)으로 검증하며 고침 (82.7% → 99.4%)
     → B. 그 판정을 중심으로 에이전트 7개를 만듦
     → C. 처음 보는 환자로 검증 (20/20, 질문으로 5/20 → 18/20)
     → D. 데모 → E. 한계 → F. 다음 계획
```

## A. 수동 스크리닝에서 출발한 판정 개발 ★ 꼭

### A-0. 핵심 메시지 (발표에서 이 문장을 꼭 말하기)
> **"AI에게 판정을 시키기 전에, 사람이 먼저 직접 판정해 봤다. 사람이 막힌 곳이 곧 AI가 틀릴 곳이었고, 그 경험을 규칙으로 만들어 프롬프트에 넣었다. 그리고 사람이 만든 정답으로 AI를 계속 검증했다."**

### A-1. 왜 수동 스크리닝부터 했나
- AI에게 "이 환자가 적격인가?"만 물으면 그럴듯하게 답하지만, **맞는지 틀린지 알 기준이 없어요.**
- 그래서 사람이 먼저 기준을 한 줄씩 직접 판정해서 ① 어디서 헷갈리는지 찾고 ② 판정 원칙을 정하고 ③ 그걸 정답으로 삼아 AI를 채점하기로 했어요.
- 수동 스크리닝은 **세 번** 했어요. 각각 결과물이 달라요.

| 단계 | 언제 | 누가·무엇을 | 결과물 |
|---|---|---|---|
| ① 사전 실험 | 10/1주 | 편두통 환자 S005 × 시험 2개를 직접 판정 | **판정 4단계, 판정 규칙, 질문 원칙, 에이전트 구조 제안, 판정 프롬프트 초안** |
| ② 평가 세트(정답) 만들기 | 10/3~10/12 | 팀원 2명이 환자 9명 × 시험 15개, 기준 173개를 각자 판정 | **평가 세트 v1.1** (`goldset/goldset_v1.json`), 팀 판정 결정 7개 |
| ③ 상세 환자 만들기 | 10/18~ | 짧은 환자 설명에 검사 수치·병력·약을 덧붙이고 직접 판정 | **상세 환자 데이터** (처음 보는 환자로 검증하는 재료) |

### A-2. ① 사전 실험: 사람이 직접 판정해 보니 (실험 0)
환자 S005(34세 여성, 시야 이상이 먼저 오는 한쪽 두통)와 실제 모집 중인 편두통 시험 2개의 기준을 한 줄씩 판정했어요.

**막힌 곳 → 정한 원칙** (이 표는 꼭 넣기)
| 사람이 막힌 곳 | 정한 원칙 |
|---|---|
| "충족/위반"으로 쓰니 제외 기준에서 헷갈림 ("75세 초과 제외"에 34세를 "위반"이라고 씀) | 선정·제외 구분 없이 **"이 기준 때문에 떨어지나?"** → 통과 / 탈락 / 모름 |
| "스크리닝 기간 28일 두통 일지"는 지금 물어볼 수 없음 | **등록 후 확인** 단계를 새로 만듦 |
| 증상은 편두통과 딱 맞는데 공식 진단 기록은 없음 | **진단과 증상(병력)을 구분**하는 규칙 |
| 기준마다 질문을 만들면 너무 많아짐 | **공통 정보는 질문 하나로** ("지금 드시는 약" 하나로 기준 4개) |
| 환자는 "항CGRP 단클론항체" 같은 말을 모름 | 쉬운 말로 질문하기 |

### A-3. ① 사전 실험: 그 원칙으로 AI 실험 4개 (웹 채팅, 10/1주)
| 실험 | 무엇을 봤나 | 결과 |
|---|---|---|
| 1. 프롬프트 비교 | 규칙 없는 프롬프트 vs 수작업 규칙을 넣은 프롬프트 | 사람 판정과 일치 **10개 중 5개 → 10개** |
| 2. 일반화 | 규칙은 그대로, 유형이 다른 시험으로 바꿈 | **11개 중 10개** 일치 (나머지 1개는 AI가 더 타당) |
| 3. 탈락 케이스 | 탈락해야 정답인 시험 2개 (나이, 조짐 병력) | 두 시험 모두 **탈락 사유를 정확히 찾음** |
| 4. 재평가 | 환자 답변을 넣고 다시 판정. 함정 답변 포함 | 판정을 정확히 바꾸고, **답 하나로 결론이 뒤집히는 것**도 맞힘 |

- 규칙이 없을 때 AI의 문제: 언급 없는 제외 기준을 그냥 통과 처리, 환자 설명에 없는 근거를 지어냄
- **결론: "수동 스크리닝이 곧 프롬프트 설계였다."**

### A-4. 자동 평가로 모델 고르기 (10/3)
- 웹에서 손으로 한 실험을 **API로 자동화**해서 모델 4개 × 케이스 6개 × 3번씩 돌렸어요(`eval/`). 사람이 매번 붙여넣고 비교하던 걸 자동 채점으로 바꿨어요.
- 사전 실험에서 찾은 문제 3개(진단·병력 혼동, 과잉 추론, 탈락 후에도 질문)를 규칙으로 고쳐 효과를 숫자로 확인했어요. 예: 탈락 후 질문 안 하기 모델별 3~5/9 → **9/9**
- 모델 비교 결과로 판정 모델을 **Sonnet 5.5**로 정했어요(비용 대비 최선, 정확도 99%).
- 교훈: 웹에서 잘 되던 프롬프트도 모델을 바꾸면 무너질 수 있어서, 모델이나 규칙을 바꿀 때마다 자동 평가를 돌려요.

### A-5. ② 평가 세트(정답) 만들기 (10/3~10/12)
- 사전 실험은 환자 1명뿐이라, 정답을 크게 만들었어요. **환자 9명 × 시험 15개, 기준 173개**를 팀원 2명이 판정했어요.
- **교차 검증**: S004·S008은 두 사람이 서로 보지 않고 따로 판정해서 비교했어요. **46개 중 43개 일치(93%)**, 갈린 3개는 모두 동의서 기준이었어요.
- 애매한 기준은 **팀 회의로 규칙을 정했어요** (꼭 보여 주기):
  1. 동의서·참여 의향 → 등록 후 확인
  2. 추론으로 탈락 같아 보여도 명시 안 됐으면 모름
  3. 내용이 공개 안 된 기준("Other", "프로토콜에 정의") → 등록 후 확인
  4. 연구자·의사 판단, 순응도, 기대 여명 → 등록 후 확인
  5. 기록에 없는 검사 수치 → 모름
- 레이블 시트를 만들 때 정답이 한쪽으로 쏠리지 않게 판정 칸은 비우고, **AI에게 판정을 묻지 않는 규칙**을 정했어요(용어 설명만 허용).

### A-6. 정답으로 검증하며 판정 고치기 (10/12~10/15)
| 버전 | 기준 일치 (173개) | 바꾼 것 |
|---|---|---|
| v1 | 143 (82.7%) | 팀 회의 전 규칙 |
| v2 | 161 (93.1%) | 회의 결정 반영 |
| **v3** | **172 (99.4%)** | AI가 틀린 17건을 유형별로 분석해서 규칙 추가 |

- 틀린 유형 예: **추정 진단을 사실처럼 씀**(유문협착증 의심 영아에게 "악성종양 없음"을 확정) → 환자 원문을 같이 주고 "추정 진단으로 다른 병 유무를 확정하지 않기" 규칙
- 함께 꼭 말할 것: 99.4%는 규칙을 고칠 때 본 데이터라 **독립 검증이 아니에요** → 그래서 ③ 상세 환자로 다시 검증 (C절)

### A-7. 수동 스크리닝에서 나온 결과물 (한 장으로 정리해서 보여 주기)
| 결과물 | 무엇 | 어디서 나왔나 |
|---|---|---|
| 판정 4단계 + 최종 판단 4단계 | 통과/탈락/모름/등록 후 확인 → 적격/적격 가능/정보 부족/부적격 | 사전 실험 수동 스크리닝 |
| 판정 프롬프트 v3 | 판정 규칙 10개 (진단·병력 구분, 추론 금지, 등록 후 확인 범위 등) | 사전 실험 → 자동 평가 → 평가 세트 불일치 분석 |
| 평가 세트 v1.1 | 환자 9명, 시험 15개, 기준 173개 정답 + 팀 결정 7개 | 팀원 2명 수동 판정 + 교차 검증 |
| 자동 평가 도구 | 모델·프롬프트를 바꾸면 바로 정답과 비교 | 사전 실험 자동화 |
| 상세 환자 데이터 | 검사 수치·병력이 들어간 환자 + 사람 판정 | 상세 환자 수동 판정 |
| 질문 원칙 → 질문 프롬프트 v2.3.3 | 공통 정보 묶기, 쉬운 말, 한 질문에 한 주제 등 | 사전 실험에서 찾은 질문 약점 → 질문 프롬프트 개선 |

## B. 에이전트별로 무슨 일을 하고, 어떻게 만들었나 ★ 꼭

### B-0. 핵심 메시지
> **"확실한 건 코드가, 해석은 AI가 한다. 그리고 각 에이전트는 실험에서 찾은 문제를 해결하려고 만들었다."**

전체 그림 (그림으로 꼭 넣기):
```
환자 설명 → ① 환자 이해 → ② 시험 검색 → ③ 기준 나누기 → ④ 판정 → ⑤ 질문 만들기
         → (환자 답변) → ⑥ 다시 판정 → ⑦ 추천
```

### B-1. 에이전트별 정리 (각 에이전트마다 "하는 일 / AI·코드 / 왜 이렇게 만들었나"를 넣기)

| # | 에이전트 | 하는 일 (입력 → 출력) | AI / 코드 | 왜 이렇게 만들었나 (개발 근거) |
|---|---|---|---|---|
| ① | **환자 이해** | 짧은 환자 설명 → 구조화된 프로필 (나이, 성별, 추정 진단, 증상, 병력, 약, 검사) | AI | 사전 실험에서 규칙이 없으면 **근거를 지어냄** → 설명에 없는 항목은 비워 두게 함. 추정 진단은 "추정"이라 판정 근거로 쓰지 않음(v3) |
| ② | **시험 검색** | 프로필 → AI가 검색어 3개를 정함 → ClinicalTrials.gov API(모집 중인 시험) → **나이·성별은 코드로 거름** → 후보 시험 | AI + 코드 | 사전 실험에서 AI가 나이·장소를 기준처럼 판정하기도, 무시하기도 함 → 기계적으로 확정되는 조건은 코드가 먼저 거름 (흔들림 없음, AI 호출 줄어듦) |
| ③ | **기준 나누기** | 시험 기준 원문 → 기준 하나씩 + 하위 조건 + 유형(의학/시간·수치/행정/등록 후 확인) + 판정에 필요한 정보 | AI | 사전 실험 4에서 **하위 조건을 실행마다 다르게 빠뜨림** → 판정 전에 미리 쪼개 두고 판정은 목록대로 확인. 시험별로 저장해서 다시 쓰면 비용이 안 듦 |
| ④ | **판정** | 프로필 + 환자 원문 + 기준 → 기준마다 4단계 판정 + **원문 인용 근거** | AI + 코드 | A절 전체가 이 에이전트 개발 과정. 규칙 v1 → v3, 82.7% → 99.4%. **나이·임신 기준은 코드가 판정**(평가 세트 21/21). AI가 기준을 빠뜨리거나 이상한 값을 내면 코드가 "모름"으로 채움(빠진 탈락 기준 때문에 부적격 환자가 적격으로 나오는 위험 방지). 최종 판단도 코드 규칙 |
| ⑤ | **질문 만들기** | 모든 후보 시험의 "모름" 기준 → 환자에게 물을 질문 (최대 5개) | 코드 + AI + 코드 | 코드가 모름 기준을 고르고 → AI가 뜻이 같은 것끼리 묶어 쉬운 말로 쓰고 → 코드가 잘못된 기준 번호·중복을 걸러요. 처음엔 글자가 똑같은 정보만 묶여서 두 시험 공통 질문이 0개였음 → AI가 뜻으로 묶게 바꿈. 질문 프롬프트는 v0 → **v2.3.3**까지 개선 (판정 영향 우선, 한 질문에 한 주제, 기간·약물명 보존, 후속 질문 원칙) |
| ⑥ | **다시 판정** | 환자 답변 → **답과 관련된 기준만** 다시 판정 → 질문을 마치면 전체 한 번 더 | AI + 코드 | 처음 초안은 답변으로 프로필을 다시 쓰고 시험 전체를 다시 판정해서 비용이 컸음 → 관련 기준만 판정. 실제 실행에서 부분 판정이 같은 답을 다르게 판정한 일이 있어서 마지막에 **전체 재판정**을 꼭 하게 함. 판정 근거에 "Q1 답변: …"이 인용됨 |
| ⑦ | **추천** | 시험별 최종 판단 → 순위 (적격 > 적격 가능 > 정보 부족, 부적격은 제외 목록 + 탈락 기준 표시) | 코드 (+ 설명은 AI) | 순위는 실행마다 바뀌면 안 돼서 **코드 규칙**으로. 같은 등급이면 통과가 많은 순 → 모름이 적은 순. 순위 이유를 설명하는 리포트(AI)는 데모에 연결 중 |

**평가용 도구** (에이전트는 아니지만 소개하기)
- **환자 역할 AI(시뮬레이터)**: 상세 환자 설명만 보고 질문에 답해서, 질문 루프를 자동으로 평가해요. 처음엔 없는 "아니요"를 지어내서 고쳤어요(C절).
- **자동 평가 스크립트**: 평가 세트·상세 환자와 AI 판정을 기준별로 비교해요.

### B-2. 기술 정보 (한 줄씩)
- 판정 모델: Claude Sonnet 5.5 (모델 4개 비교 후 결정)
- 시험 데이터: ClinicalTrials.gov API v2 (공개, 무료)
