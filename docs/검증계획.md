# 검증 계획 (10/28 회의 결정: 기능 추가보다 검증·신뢰성 강화)

> 목표: "규칙이 좋아 보인다"가 아니라 **어떤 규칙이 어떤 오류를 고쳤는지, 과적합은 아닌지**를 숫자로 증명.

## 실험 1. 판정 프롬프트 아블레이션 (러너: `scripts/eval_prompt_ablation.py`)

모델(Sonnet 5.5)·입력 형식 동일, **시스템 프롬프트만 교체** (`prompts/ablation/`):

| 조건 | 내용 | 검증하는 것 |
|---|---|---|
| A | 무규칙 (역할·라벨·출력 형식만) | 베이스라인 |
| B | **AI 자작 규칙 (대조군)** — AI가 스스로 쓴 규칙 고정 | 수동 스크리닝(0단계)의 효과 — B≈E면 수작업 불필요했단 뜻 |
| C | v1 (킥오프 초기 규칙) | 초기 규칙 기여 |
| D | v2 (회의 결정 반영) | 팀 라벨 표준의 기여 |
| E | v3 (현재 최종) | 최신 규칙 기여 |
| F | v3 + 규칙 11·12 (보류분) | "상세환자↑ 전체↓" 현상 정량화 → 채택 결정 근거 |

- **각 조건 3회 반복** — 3회 모두 틀리는 기준 = 규칙 문제 / 회차마다 다른 기준 = 원래 흔들림(규칙 탓 아님)
- 지표: 전체 일치율, **확정(통과·탈락) 판정 정확도**(위험 오류 분리), 일관 오류 수, 조건 간 **오류 전이표**(뭐가 고쳐지고 뭐가 새로 깨졌나)
- LLM 판정만 평가 (코드 검산 제외 — 프롬프트 효과 분리). 실제 파이프라인엔 검산이 덧붙음
- 실행: `--gen-control`(B 생성, 완료) → `--smoke`(완료) → **`--submit`(배치 API 50% 할인, 예상 $3~5, 중단 후 재개 가능)** → `--report`
- 담당: 러너·대조군 = 해준 / 실행·오류 분석 = 인선(+주희 보조)

## 실험 2. 독립 테스트 세트 (담당: 주희 + 1명)

- 새 환자 4명: 기존 확장 2 + **새 질환 2** (골드셋에 없는 질환)
- **2명이 독립 판정** → 사람 간 일치율도 산출 (기존 교차 판정 93% 선상인지)
- 오염 방지: ⓐ 본인 판정 완료 전 AI 판정 열람 금지 (용어 설명 도움은 허용) ⓑ **이 세트로 프롬프트 수정 금지 — 측정 전용 1회용**
- 프롬프트 동결(실험 1 승자) 후 1회만 평가 → "블라인드 세트에서 X%"

## 실험 3. 검색 검증·개선 (담당: 해준, TrialGPT 방식 참고)

1. 검색어 1~3 → 5~8개 다양화 (진단명 구체→일반 + 증상 + 동의어)
2. per_query 50 → 200 (3건 회수 검증됨)
3. 관련성 필터 → **관련도 랭킹**(Haiku 점수화, 호출 수 동일)
4. **recall@k 곡선** 측정 → 후보 수 N 확정 (데모 5 / 평가 10 예상)
- 개선 전(풀 67%·상위5 40%) 대비 효과를 발표 수치로

## 판정 기준 결정 대기 2건 (실험 1 결과로 판단)

- 규칙 11·12: 조건 F의 오류 전이표 보고 채택/문구 수정/폐기 결정
- "기억나지 않아요": 제안 — **모름 유지 + 재질문 금지** (독립 세트 작성 지침에도 명시)

## 예산·규칙

- 총 예상 **$6~9** (아블레이션 $3~5 배치 + 검색 $0.5 + 독립 세트 평가 ~$1)
- 비용 실행 전 단톡방 공지 (팀 규칙)
