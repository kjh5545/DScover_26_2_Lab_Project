# 역할 분담과 진행 방식 (2026-10-09 회의 결정)

> 다음 점검: **2026-10-16 (금)** · 회의 없이 **노션에 각자 진행 상황 공유**
> 시험 기간이라 이번 주는 **최소 목표**만 해도 충분해요. 여유가 있으면 "여유 있으면" 항목까지.

## 회의에서 정한 것
1. **역할 확정**: 아래 표대로 진행
2. **언급 없는 제외 기준은 "모름" 유지** (안전 우선). 평가 세트 v1은 그대로 사용
3. 서현·인선이 시험 일정이 더 바빠서, **해준이 5번 질문 에이전트 일부(코드 쪽)를 도움**
4. 다음 점검은 1주 뒤, 회의 대신 노션 공유

## 역할
| 이름 | 역할 | 이번 주 최소 목표 (~10/16) | 튜토리얼 |
|---|---|---|---|
| **주희** | 판정 (4·6·7번) | 해준 코드를 저장소에 합치기, 판정 불일치 17건 분석 | `docs/튜토리얼_주희.md` |
| **해준** | 연결 (1·2·3번, 파이프라인, 데모) + 5번 코드 | 코드를 GitHub에 올리기, 질문 재료 모으는 코드 초안 | `docs/튜토리얼_해준.md` |
| **서현** | 5번 질문 프롬프트 (코딩 없음) | 질문 생성 프롬프트 v1 만들어 보기 | `docs/튜토리얼_서현.md` |
| **인선** | 상세 환자·발표 기획 (코딩 없음) | 상세 환자 1명 쓰고 판정하기 | `docs/튜토리얼_인선.md` |

## 전체 흐름과 누가 무엇을 넘기는지
```
환자 설명
  │
  ▼  [해준] 1번 환자 이해 → 2번 시험 검색(나이·성별은 코드로 거름) → 3번 기준 파싱
  ▼  [주희] 4번 판정 (통과/탈락/모름/등록 후 확인, 최종 판단은 코드 규칙)
  │
  ├─▶ data/handoff/<환자ID>.json  ← 팀 공통 결과 파일 (형식: docs/HANDOFF.md)
  │
  ▼  [서현 프롬프트 + 해준 코드] 5번 질문 생성: "모름" 기준 + 필요한 정보 → 질문 3~5개
  ▼  [주희] 6번 재평가: 답변을 받으면 관련 기준만 다시 판정
  ▼  [주희] 7번 추천·설명
  ▼  [해준 구현 / 인선 기획] 데모 화면

[인선] 상세 환자 ─▶ [주희] 통과·탈락 판정 정확도 평가
[서현] 질문 품질 기준 ─▶ [해준] 5번 코드 / [주희] 6번 테스트
```

## 짝
- **서현 ↔ 해준**: 서현이 만든 질문 프롬프트를 해준이 코드로 붙여요 (원래 주희와 짝이었는데, 해준이 5번을 돕게 되어 변경)
- **인선 ↔ 주희**: 인선의 상세 환자로 주희가 판정 정확도를 재요
- 막히면 짝에게 바로 물어보기


## 공통 규칙
- **데이터 형식(`docs/HANDOFF.md`)을 바꿀 때는 노션이나 단톡방에 먼저 알리기.** 질문 생성, 추천, 데모가 모두 이 형식을 읽어요
- **API 비용이 드는 실행은 돌리기 전에 한 줄 알리기** (공용 예산 약 $100, 지금까지 약 $15 사용)
- **API 키는 GitHub·노션·단톡방에 올리지 않기.** 각자 `.env` 파일에만
- 코드는 각자 브랜치에서 작업하고, main에 합치기 전에 한 명 이상 확인
- 1위 팀 원본 자료는 공유하지 않기 (분석 내용만 공유)
