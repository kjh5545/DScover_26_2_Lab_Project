## Step 1. 코드를 GitHub에 올리기 (1시간)
해준님 코드가 지금 팀에서 가장 앞서 있어요 (평가 세트 기준 판정 일치 90.2%, 최종 판단 15/15). 이걸 **팀 표준 파이프라인**으로 쓰려고 해요.

1. 저장소를 받아 브랜치 만들기
   ```bash
   git clone https://github.com/kjh5545/DScover_26_2_Lab_Project.git
   cd DScover_26_2_Lab_Project
   git checkout -b feature/pipeline
   ```
2. 해준님 코드(`scripts/`, `docs/HANDOFF.md`, 에이전트 코드 등)를 복사해 넣기
3. **올리기 전 확인**
   - API 키가 코드에 직접 들어 있지 않은지 (`.env`에서 읽는지)
   - `data/handoff/` 결과 파일은 올릴지 정하기. 예시 1개(S005)만 올리면 서현님이 형식을 보기 좋아요
   - 기존 `agents/` 폴더와 겹치는 파일이 있으면 해준님 것을 우선. 정리는 주희가 리뷰하면서 같이 할게요
4. 커밋하고 push → GitHub에서 Pull Request 만들기 → 주희에게 리뷰 요청
   ```bash
   git add -A
   git commit -m "해준 1~4번 파이프라인 추가"
   git push origin feature/pipeline
   ```

## Step 2. 형식 문서(`docs/HANDOFF.md`) 확정 (30분)
"깃허브 형식 확정되면 맞추겠다"고 하셨는데, **해준님의 `HANDOFF.md`를 팀 공식 형식으로 정하는 게** 가장 빨라요. 다른 사람들이 이 형식을 기준으로 일하게 돼요.

문서에 이 세 가지만 분명하면 돼요.
- **판정 값**: 파일 안의 `verdict` 값과 한국어 판정의 대응 (예: `unknown` = 모름). 평가 세트는 한국어 판정을 쓰고 있어서, 대응표가 있어야 평가할 때 헷갈리지 않아요
- **질문 생성에 쓰는 필드**: `verdict == "unknown"` 항목과 `needed_info`
- **추천에 쓰는 필드**: `final_judgment`

예시 파일 한 개(`data/handoff/S005.json`)를 같이 올려 주시면, 서현님이 실제 모양을 보고 프롬프트를 짤 수 있어요.

## Step 3. 5번 질문 에이전트 코드 (여유 있으면 시작)
서현님이 **질문 문장을 만드는 프롬프트**를 설계하고, 해준님은 그 앞뒤의 **코드**를 맡아요.

```
handoff/<환자>.json
  → ① 질문 재료 모으기 (코드)       ← 해준
  → ② 같은 정보 묶기 (코드)         ← 해준
  → ③ 질문 문장 만들기 (LLM)        ← 서현 프롬프트
  → questions/<환자>.json
```

**① 질문 재료 모으기**
- 환자의 모든 후보 시험에서 `verdict == "unknown"` 항목과 `needed_info`를 모아요
- **최종 판단이 부적격인 시험은 빼요.** 이미 탈락이 확정된 시험에 대해 묻는 건 의미가 없어요
- "등록 후 확인" 항목도 빼요. 지금 물어봐도 답할 수 없는 정보예요

**② 같은 정보 묶기 (1위 팀에서 가져온 핵심 아이디어)**
- 여러 시험이 같은 정보를 필요로 하면 **질문 하나로** 묶어요 (예: 시험 3개가 모두 "최근 신장 기능 검사"를 요구)
- 묶은 뒤 **걸린 시험 수가 많은 정보부터** 정렬해요. 같으면 걸린 기준 수가 많은 순
- `needed_info` 문구가 시험마다 조금씩 다를 수 있어요 ("신장 기능" vs "크레아티닌"). 처음엔 문구가 같은 것끼리만 묶고, 나중에 LLM으로 비슷한 것끼리 묶는 걸 고려하면 돼요
- 상위 3~5개만 질문으로 넘겨요

**③ 질문 문장 만들기**
- 서현님 프롬프트에 ②의 결과를 넣어 질문 문장을 받아요
- 서현님 프롬프트가 나오기 전에는 간단한 임시 문장(예: "{needed_info}를 알려주세요")으로 흐름만 만들어 두면 돼요

**출력 형식 제안** (`questions/<환자>.json`)
```json
{
  "patient_id": "S004",
  "questions": [
    {
      "text": "최근 신장 기능 검사(크레아티닌) 결과를 받은 적 있나요?",
      "needed_info": "renal function",
      "resolves": [{"trial": "NCT04369560", "criteria": ["I5"]}],
      "priority": 1
    }
  ]
}
```
이 형식도 `HANDOFF.md`에 같이 적어 주세요. 주희의 6번 재평가가 `resolves`를 보고 관련 기준만 다시 판정해요.

## Step 4. 관련 없는 시험 거르기 (다음 주 이후)
키워드 검색만으로는 엉뚱한 시험이 걸려요. 평가 세트의 **S007(생후 3개월 영아 유문협착증)에게 성인 악성 위 출구 폐쇄 수술 시험**이 걸린 게 대표적이에요. 1위 팀은 검색 뒤에 "이 시험이 정말 이 환자의 병에 관한 것인가"를 시험 제목·질환명·요약만 보고 판단하는 단계를 뒀어요. 같은 장기나 같은 증상이라고 관련 있는 게 아니라는 규칙이 핵심이에요.
