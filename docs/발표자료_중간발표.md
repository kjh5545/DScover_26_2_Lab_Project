## 1. 문제: 짧은 환자 설명으로 임상시험 찾기

- **과제**: 성균관대 AIHC Lab *Healthcare Agentic AI Challenge 2026*. 짧은 환자 설명을 받아 ClinicalTrials.gov에서 임상시험을 찾고, 선정·제외 기준과 한 줄씩 대조하고, 모자란 정보는 질문으로 채운 뒤, 맞는 시험을 근거와 함께 추천해요.
- **평가 비중**: 매칭 정확성 30% · 랩 내 정성 평가 30% · **발표 40%**
- **어려운 점**: 환자 설명은 1~2문장인데 시험 기준은 수십 줄이에요. 예시 (S004):
  > A 68-year-old man with a long smoking history presents with painless gross hematuria. CT urography reveals a mass in the bladder wall.
  >
  > (68세 남성, 오랜 흡연력, 통증 없는 육안적 혈뇨, CT 요로조영술에서 방광벽 혹)

  이 두 문장으로 방광암 MRI 연구의 기준 13개를 판정해야 해요. 대부분은 정보가 없어요.

## 2. 우리 접근: "모른다"를 따로 다루고, 정확도를 사람이 만든 정답으로 잰다

### 2-1. 판정 4단계
| 판정 | 뜻 | 예 (S004) |
|---|---|---|
| ✅ 통과 | 이 기준에 걸리지 않음이 확인됨 | 68세 → "18~90세" 통과 |
| ❌ 탈락 | 이 기준에 걸림이 확인됨 | "CT에서 퍼진 소견 없음" → "4기 환자 대상" 탈락 |
| ❓ 모름 | 지금 물어보면 알 수 있는데 정보가 없음 | 신장 기능 수치 |
| 🕒 등록 후 확인 | 시험에 지원해야 알 수 있음 | 서면 동의, 연구자 판단, 참여 의향 |

- **"등록 후 확인"을 따로 둔 이유**: 동의서나 연구자 판단은 환자에게 물어도 답이 없어요. 모름과 섞으면 쓸데없는 질문이 늘어요.
- 최종 판단도 코드 규칙으로 계산해요: 탈락이 하나라도 있으면 **부적격** → 모름이 남으면 **정보 부족** → 등록 후 확인만 남으면 **적격 가능** → 모두 통과면 **적격**

### 2-2. 1위 팀에서 배운 것과 우리 차별점
- 지난 대회 1위 팀의 교훈: **"정보가 없는 것과 조건을 못 맞추는 것은 다르다."** 그래서 모르는 정보는 질문으로 찾는 데 집중했어요.
- 1위 팀이 스스로 밝힌 약점은 **기준 하나하나의 판정 정확도**였어요. 우리는 여기에 집중했어요. 사람이 만든 정답으로 판정을 검증하고, 틀린 유형을 분석해서 규칙을 고쳤어요.
- ⚠️ 1위 팀 자료는 연구실 참고 자료라 원본은 공유하지 않기로 했어요. 발표에서 1위 팀 수치를 말해도 되는지는 확인이 필요해요(11절).

## 3. 시스템 구조: 에이전트 7개

```
환자 설명
 → ① 환자 이해        짧은 설명 → 구조화된 프로필
 → ② 시험 검색        ClinicalTrials.gov 검색 + 나이·성별은 코드로 거름
 → ③ 기준 나누기      시험 기준 원문 → 기준 하나씩
 → ④ 판정            기준마다 통과/탈락/모름/등록 후 확인 + 근거 인용
 → ⑤ 질문 만들기      여러 시험의 "모름"을 모아 환자용 질문으로
 → (환자 답변)
 → ⑥ 다시 판정        답과 관련된 기준만 다시 판정, 끝나면 전체 한 번 더
 → ⑦ 추천            최종 판단 등급순으로 순위 (코드 규칙)
```

- **확실한 건 코드가, 해석은 AI가.** 코드: 나이·임신 기준 판정, 최종 판단 계산, 추천 순위, 질문 검사. AI: 환자 문장 이해, 기준 해석, 질문 문장 쓰기.
- **판정 근거에 원문을 인용**해요. 예: `Q4 answer: "하루 한 갑 정도씩 45년 동안 피웠고…" This is about 45 pack-years, which is ≥15.`
- 1~4번은 공용 함수(`run_intake`) 하나로 돌아서, 데모와 명령줄 실행이 같은 코드를 써요 (해준, 10/20).
- 출처: `docs/00_역할분담과_진행방식.md`, `src/pipeline.py`

## 4. 판정 정확도: 사람이 만든 정답으로 검증하며 고치기

### 4-1. 판정 규칙의 출발: 사전 실험 (10/3)
- 편두통 환자(S005) × 시험 4개를 **손으로 스크리닝**해서 판정 규칙을 찾았어요. 예: 진단과 병력 구분, 명시 안 된 건 추론으로 확정하지 않기.
- 이 규칙을 프롬프트에 넣었더니 수작업 판정과 일치하는 기준이 **10개 중 5개 → 10개**가 됐어요. 다른 시험에서도 11개 중 10개가 일치했어요.
- 출처: `사전실험_정리.md`

### 4-2. 평가 세트 (정답) 만들기 (10/3~10/12)
- 환자 9명 × 시험 15개, **기준 173개**를 **서현·인선**이 직접 판정했어요. 두 사람 판정 일치도는 **93%**예요.
- 애매한 기준은 팀 회의로 정했어요.
  - 동의서·참여 의향 → 등록 후 확인
  - 명시되지 않은 건 추론으로 탈락 확정 안 함
  - 연구자 판단, 기대 여명 → 등록 후 확인
  - 기록에 없는 검사 수치 → 모름
- 출처: `goldset/평가세트_v1.md`

### 4-3. 틀린 유형을 분석해서 규칙 고치기
| 버전 | 기준 일치 | 최종 판단 | 무엇을 바꿨나 |
|---|---|---|---|
| v1 | 143/173 (82.7%) | 13/15 | 팀 회의 전 규칙 |
| v2 | 161/173 (93.1%) | 15/15 | 회의 결정 반영 (등록 후 확인 등) |
| **v3** | **172/173 (99.4%)** | **15/15** | 틀린 17건을 유형별로 분석해서 규칙 추가 |

- **v3에서 고친 유형** (v2에서 틀렸다가 맞힌 11건)
  - 추정 진단을 사실처럼 씀 (5건) → 환자 원문을 같이 주고 "추정 진단으로 다른 병 유무를 확정하지 않기"
  - 기록에 없는 검사 수치를 "등록 후 확인"으로 분류 (3건) → "기록에 없는 수치는 모름"
  - 영아라서 설문 불가라고 추론 (1건) → "명시 안 된 건 추론으로 확정 금지"
- **나이·임신 기준은 코드가 판정**해요. AI도 이미 맞혔지만, 모델이나 프롬프트가 바뀌어도 확실한 기준에서 실수하지 않게 하는 안전장치예요.
- **비용**: 판정 모델을 Opus 5에서 **약 2.5배 저렴한 Sonnet 5.5**로 바꾸면서도 정확도가 올랐어요. 평가 세트 전체 판정 1회에 **$0.13**이에요(일괄 처리 50% 할인).
- 남은 1건(S006 E1, "코 점막의 괴사 딱지 = 활동성 병변?")은 판단이 갈리는 기준이라 정답 재검토 안건이에요.
- **⚠️ 꼭 같이 말할 것**: 99.4%는 규칙을 고칠 때 본 데이터라 **독립 검증이 아니에요**. 정답의 71%가 "모름"이라 통과·탈락 정확도는 거의 재지 못했어요. 그래서 5절에서 새 환자로 검증했어요.
- 출처: `eval/결과_4차_판정v3_Sonnet.md`

## 5. 새 환자 검증: 상세 환자 (10/18~10/22)

### 5-1. 상세 환자란
- **인선**이 짧은 환자 설명 뒤에 검사 수치, 병력, 복용약을 덧붙인 "상세 환자"를 만들고, 기준마다 직접 판정했어요. 판정 규칙을 만들 때 **보지 않은 데이터**예요.
- 환자 2명: **S004**(68세 남성, 방광암 의심), **S008**(60세 여성, 특발성 폐섬유증). 시험 4개, 기준 46개예요.
- 판정이 애매한 곳은 주희가 다시 판정했어요. 예: "CT에서 원격 전이 소견 없음"이 명시돼 있으면 "전이" 기준은 통과.
- S004 상세 설명 일부:
  > … Cystoscopy two days ago revealed a papillary bladder tumor on the left bladder wall … TURBT is scheduled for next week … Serum creatinine is 1.0 mg/dL (institutional upper limit of normal: 1.3 mg/dL) …

### 5-2. 검증 A: 정보가 다 있으면 판정을 잘하나?
| | 결과 |
|---|---|
| 정답이 통과·탈락인 기준 | **20/20** |
| 기준 일치 (모름·등록 후 확인 포함) | 43/46 |
| 최종 판단 | 4/4 |

- 틀린 3개는 모두 **AI가 명시되지 않은 것을 추론해서 통과**를 준 경우예요. 예: "IPF로 진단받았으니 ATS/ERS 기준도 충족" (11절 한계).

### 5-3. 검증 B: 정보를 가리면 질문으로 되찾나? (1위 팀 평가 방식)
- **방법**: 상세 정보를 가리고 짧은 설명에서 시작해요. AI가 질문을 만들면, **환자 역할 AI(시뮬레이터)**가 상세 설명만 보고 답해요. 답과 관련된 기준을 다시 판정하고, 최대 3라운드(라운드당 질문 5개)를 돈 뒤 마지막에 전체를 한 번 더 판정해요. 끝나면 상세 환자 정답과 비교해요.

| | 질문 전 | **질문 후** |
|---|---|---|
| 정답이 통과·탈락인 기준 | 5/20 | **18/20** |
| 기준 일치 | 31/46 | **41/46** |
| 모름 개수 | 36 | **20** |
| 최종 판단 | | 3/4 |
| AI가 만든 질문 | | 27개 (환자당 2~3라운드) |

- **모름이 20개 남은 건 상세 설명에도 없는 정보라서예요.** 환자가 "모르겠어요"라고 답했고, AI는 없는 정보를 지어내지 않았어요.

## 6. 질문 만들기 (서현 프롬프트 v0 → v2.3.3)

### 6-1. 질문을 만드는 3단계
| 단계 | 누가 | 하는 일 |
|---|---|---|
| ① 고르기 | 코드 | 모든 후보 시험의 "모름" 기준을 모아요. 부적격 시험, 등록 후 확인은 빼요 |
| ② 묶고 쓰기 | AI (**서현 프롬프트**) | 뜻이 같은 정보는 시험이 달라도 한 질문으로 묶고, 환자가 이해할 쉬운 말로, 우선순위대로 써요 |
| ③ 검사 | 코드 | 없는 기준 번호와 중복을 빼고 5개로 잘라요 |

### 6-2. v2.3.3 원칙 (서현, 10/21)
- 우선순위: **판정 영향 → 공통성(여러 시험에 도움) → 시험별 균형**
- 한 질문에 한 주제. 예: "두통 날 수"와 "전조 횟수"는 다른 측정값이라 나누고, "임신·수유"와 "피임"도 나눠요.
- 원문의 **기간·기준일·용량·약물명·투여 경로·예외 범위를 바꾸지 않기**. 월별 조건을 월평균으로 바꾸지 않아요.
- 특정 진단이 필요한 기준은 **정확한 진단명**으로 묻기. 증상만으로 진단을 전제하지 않아요. 판정 규칙과 같은 원칙이에요.
- 민감한 질문(임신 등)이라는 이유만으로 뒤로 미루지 않기
- 이미 답한 내용은 다시 묻지 않기. 같은 기준의 **아직 모르는 부분만** 후속 질문으로 묻기

### 6-3. 바뀐 질문 예시 (S005 편두통 환자, 같은 입력)
| v2.1 (10/17) | v2.3.3 (10/22) |
|---|---|
| "최근 3개월 동안 한 달에 두통이 있었던 날은 대략 며칠이었고, **그중** 시야에 반짝이는 점이 먼저 나타난 두통은 몇 번 정도였나요?" → 측정값 2개를 한 질문에, 기준에 없는 "최근 3개월" | ① "전조 증상이 나타난 편두통 발작이 있었던 **달마다, 그 연도와 월, 그 달의 발작 횟수**를…" ② "두통이 있었던 날이 각 달에 며칠이었는지 **달별(연도와 월)로**…" → 둘로 나누고, 달별로 |
| "현재 임신 중이거나 수유 중이신지, **또는 피임을 하고 계신지**…" → 다른 주제를 섞음 | 임신·수유와 피임을 섞지 않음 |
| 진단명 대신 증상으로 물음 | "의사에게 만성 편두통, 군발두통, 전조가 있는 편두통 중 **진단받은 것**이 있나요?" → 두 시험에 공통인 진단 질문 하나로 |

### 6-4. 코드도 같이 바꾼 것 (10/22, 서현이 짚은 충돌 2개)
- **질문 순서**: 전에는 코드가 "여러 시험 질문 먼저 → 시험별로 번갈아"로 다시 정렬했어요. 이게 "판정 영향 우선"과 충돌해서, 이제 AI가 정한 순서를 따라요.
- **후속 질문**: 전에는 한 번 물은 기준을 다시 안 물었어요. 이제는 답을 받았는데도 모름이면 **한 번 더** 물을 수 있어요. 건너뛴 질문이나 두 번 물은 기준은 다시 안 물어요.
- 출처: `src/question_builder.py`, 비교 실행: `data/processed/question_compare_10-22/`

## 7. 시험하다 배운 것: 환자 역할 AI도 검증해야 한다 (10/18)

## 8. 데모 (해준 구현, 10/20 디자인)

## 11. 한계 (발표에서 정직하게)

- **상세 환자가 2명, 기준 46개**라 작아요.
- 질문 루프의 답은 사람이 아니라 **시뮬레이터**가 했어요. 시뮬레이터가 결과지 내용까지 친절하게 말해 주는 경향이 있어서, 실제 환자보다 정보가 잘 모일 수 있어요.
- **AI가 추론으로 통과를 주는 경우**가 있어요. 예: "IPF 진단이 있으니 ATS/ERS 기준도 충족"
  - 규칙을 넣어 봤더니 상세 환자는 좋아지고(+2) 평가 세트는 나빠져서(−1) 보류했어요.
  - 같은 데이터를 보고 만든 규칙이라, 새 환자로 검증한 뒤 넣기로 했어요.
- **"기억나지 않아요"를 어떻게 볼지**: 판정 AI가 "심부전 진단받았다는 얘기는 기억나지 않아요"를 "없음"으로 읽고 통과를 줬어요. 모름으로 볼지 팀 회의 안건이에요.
- **기록을 받는 통로가 없어요**: v2.3.3은 "결과지를 제공할 수 있나요?"처럼 기록을 요청하는 질문이 많은데, 지금 시스템에는 파일을 올리는 기능이 없어요.
- 정답 자체가 애매한 기준이 있어요. 예: 혈뇨 시험 E2 "최근 2년 안에 혈뇨로 검사받은 적"에서, "혈뇨 때문에 받은 검사"라고 명시돼야 하는지.
