## Step 1. 해준 코드 리뷰하고 합치기 (1~2시간)
해준이 1~4번 파이프라인을 이미 만들었어요 (평가 세트 기준 판정 일치 90.2%, 최종 판단 15/15). **이걸 팀 표준으로** 삼아요.

1. 해준이 `feature/pipeline` 브랜치로 Pull Request를 올리면 리뷰해요
2. 확인할 것
   - API 키가 코드에 없는지 (`.env`에서 읽는지)
   - 실행 방법이 README에 있는지 (`python scripts/run_intake.py S005`)
   - `docs/HANDOFF.md`에 판정 값 대응표(`unknown` = 모름 등)가 있는지
3. 기존 `agents/` 폴더 정리
   - 해준 코드와 겹치는 부분은 해준 쪽을 남기고, `agents/`는 지우거나 `agents_old/`로 옮겨요
   - 단, 두 가지는 해준 코드에 없다면 옮겨 주면 좋아요: **근거 인용이 원문에 실제 있는지 확인하는 코드** (`agents/patient_agent.py`의 `check_quotes`), **평가 세트와 같은 결과를 내는 규칙 기반 파서** (`agents/parse_rules.py`)
   - `agents/TODO_해준.md`는 `docs/튜토리얼_해준.md`로 대체됐으니 지워요
4. 합친 뒤 main에서 `python scripts/run_intake.py S005`가 돌아가는지 확인

## Step 2. 판정 불일치 17건 분석 (1~2시간)
해준 파이프라인의 4번 판정은 173개 중 156개가 정답과 같고, **17개가 달라요.** 해준이 "안건 12"로 정리해 둔 두 가지가 핵심이에요.

**① 검사 수치 기준의 표준**
- 예: "크레아티닌 정상 상한 1.5배 미만" 같은 기준에서 환자 설명에 수치가 없을 때
- 사람 정답은 모두 **모름**. 질문 칸에 "최근 검사 결과를 받은 적 있나요?"처럼 씀
- AI가 다르게 판정한 경우가 있다면, 프롬프트에 "검사 수치·점수·날짜가 없으면 모름"을 명시하면 돼요 (1위 팀의 판정 규칙과도 같아요)

**② S007 추정 진단 추론**
- S007(생후 3개월, 유문협착증 의심)이 성인 악성 위 출구 폐쇄 수술 시험에 걸린 케이스
- 사람 정답: I4 나이(18세 초과) **탈락**, E1 나이(18세 미만) **탈락**, I1 악성종양은 "진단명 명시 없음"이라 **모름**
- AI가 "영아라 악성종양일 리 없다"고 I1을 탈락으로 추론했다면, 회의 결정("명시되지 않은 걸 추론으로 탈락 확정 금지")에 따라 모름이 맞아요. 다만 최종 판단(부적격)은 나이로 이미 맞으니 영향은 작아요

**분석 방법**
1. 해준 결과에서 정답과 다른 17개를 표로 뽑아요 (케이스, 기준, 정답, AI 판정, AI 근거)
2. 유형별로 묶어요: 수치 없음 / 추론 탈락 / 동의서 / 기타
3. 유형마다 "프롬프트 규칙으로 고칠 것"과 "정답을 다시 볼 것"을 나눠요. 정답을 고쳐야 할 것 같으면 혼자 바꾸지 말고 노션에 안건으로 올려요
4. 결과를 `eval/결과_3차_불일치분석.md`에 정리

## Step 3. 프롬프트 개선 (여유 있으면)
- 해준의 4번 프롬프트(해준 쪽 "v2")를 복사해 새 버전 파일로 만들고, Step 2에서 찾은 규칙을 넣어요
- 평가는 우리 평가 도구로 해요
  ```bash
  cd eval
  python run_eval.py --goldset --rules <새 프롬프트 파일> --models claude-sonnet-5-5 --repeats 3
  ```
  해준 프롬프트는 출력 형식이 다를 수 있으니, `run_eval.py`의 출력 형식 부분과 맞는지 먼저 확인해요. 맞지 않으면 해준 쪽 채점 스크립트로 재도 돼요
- 비용: 15케이스 × 3회 ≈ $3. 돌리기 전에 노션에 한 줄 알리기
- 바꾼 규칙과 점수 변화를 `eval/` 아래에 기록해요 (발표 때 "규칙을 고칠 때마다 수치로 확인했다"는 근거가 돼요)

**1위 팀에서 가져올 만한 것 (판정 쪽)**
- 근거 부족 사유 구분: "3개월 전 결과는 정상인데 시험은 14일 이내 결과를 요구" → 모름 + "최신 결과 필요" 표시
- 판정 근거 인용을 코드로 검증: AI가 인용한 표현이 환자 설명에 실제 있는지 확인하고, 없으면 다시 판정
- 최종 판단은 코드 규칙으로 (해준이 이미 구현)

## Step 4. 6번 재평가 (다음 주 이후)
- 입력: 해준·서현의 질문 파일(`questions/<환자>.json`)과 환자 답변
- 답변으로 해결되는 기준(`resolves`)만 다시 판정하고, 나머지 판정은 그대로 둬요 (1위 팀 방식)
- 사전 실험의 재평가 테스트(`screening/llm_reeval_test.md`)에서 쓴 "이전 → 이후" 표시와 함정 답변(긴장형 두통 예외, 급성기 약 구분, 날짜 계산)을 테스트 케이스로 재사용할 수 있어요

## Step 5. 7번 추천·설명 (후반)
- 최종 판단 + 남은 모름 수 + 질문으로 해결 가능한지로 순위
- 시험마다 근거 리포트: 어떤 기준이 어떤 환자 정보와 맞았는지, 무엇이 남았는지
- 모든 출력에 의료 면책 문구

## Step 6. 인선 상세 환자로 평가 (인선 결과가 오면)
- 상세 환자 + 인선 판정을 평가 세트에 추가 (`screening/labeling/_export_goldset.py` 방식 참고)
- 통과·탈락 판정 정확도를 따로 재요. 지금은 정답의 75%가 모름이라 이 정확도를 잴 수 없었어요
- 1위 팀 지표도 같이: 짧은 환자에서 시작해 질문 후 상세 환자 정답과 얼마나 같아지는지 (적격 복원율, 부적격 정리율, 잘못 탈락·섣부른 적격 같은 안전 오류)
