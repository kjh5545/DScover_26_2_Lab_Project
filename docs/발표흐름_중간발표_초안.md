- 서현은 질문 프롬프트, 인선은 평가 세트와 상세 환자를 직접 만들어서 자기 작업을 설명하는 구성이에요. 바꿔도 돼요.

## 장표별 흐름

### 1. 표지
- 제목 예: "인터랙티브 임상시험 추천 멀티 에이전트" / DScover 26-2 · Healthcare Agentic AI Challenge 2026
- 팀원: 주희, 해준, 서현, 인선

### 2. 문제: 환자에게 맞는 임상시험 찾기
- **말할 것**: 임상시험마다 선정·제외 기준이 수십 줄이에요. 환자 설명은 짧아서 판정에 필요한 정보가 대부분 없어요.
- **보여 줄 것**: 짧은 환자 설명 예시 (S004 원문 2문장)
  > A 68-year-old man with a long smoking history presents with painless gross hematuria. CT urography reveals a mass in the bladder wall.
- 이 정도 정보로 기준 13개를 판정해야 하는 상황이라는 걸 보여 줘요.

### 3. 우리 접근: "모른다"를 따로 다룬다
- **말할 것**: 정보가 없는 것과 조건을 못 맞추는 것은 달라요. 그래서 판정을 4단계로 해요.
- **보여 줄 것**: 판정 4단계 표
  | 판정 | 뜻 | 예 |
  |---|---|---|
  | ✅ 통과 | 이 기준에 걸리지 않음이 확인됨 | 68세 → "18~90세" 통과 |
  | ❌ 탈락 | 이 기준에 걸림이 확인됨 | "CT에서 퍼진 소견 없음" → "4기 환자 대상" 탈락 |
  | ❓ 모름 | 지금 물어보면 알 수 있는데 정보가 없음 | 신장 기능 수치 |
  | 🕒 등록 후 확인 | 시험에 지원해야 알 수 있음 (동의서, 연구자 판단) | "서면 동의 가능" |
- **차별점**: "등록 후 확인"은 질문해도 답이 없는 기준을 따로 빼서, 쓸데없는 질문을 줄여요.

### 4. 시스템 구조: 에이전트 7개
- **보여 줄 것**: 흐름도
  ```
  환자 설명 → ① 환자 이해 → ② 시험 검색(나이·성별 거름) → ③ 기준 나누기 → ④ 판정
            → ⑤ 질문 만들기 → (환자 답) → ⑥ 다시 판정 → ⑦ 추천 순위·설명
  ```
- **말할 것**: 확실한 건 코드가, 해석은 AI가 맡아요.
  - 코드가 하는 일: 나이·임신 기준 판정, 최종 판단 계산, 추천 순위
  - AI가 하는 일: 환자 문장 이해, 기준 해석, 질문 문장 쓰기
- 판정 모델: Claude Sonnet 5.5
- **[빈칸: 해준]** 파이프라인과 데모 연결 확인 결과, `run_intake` 정리 여부
- 출처: `docs/00_역할분담과_진행방식.md`, `docs/HANDOFF.md`

### 5. 질문 만들기: 여러 시험에 공통으로 필요한 것부터
- **말할 것**: 시험마다 따로 물으면 환자가 같은 질문을 여러 번 받아요. 그래서 여러 시험의 "모름"을 모아 한 질문으로 묶어요.
- **보여 줄 것**: 3단계 = 코드가 고르기 → AI가 묶어서 쉬운 말로 쓰기(**서현 프롬프트 v2.1**) → 코드가 검사
- 예: S008 질문 하나로 두 시험의 기준을 한 번에 정리
  > Q2. 최근 한 달 사이에 숨찬 증상이 갑자기 심해져서 입원하거나 응급실에서 치료받은 적이 있나요?
  > → "아니요, 18개월 동안 서서히 심해졌고 입원한 적 없어요" → 시험 1 E3 통과, 시험 2 I3 탈락(입원 환자 대상 시험)
- **[빈칸: 서현]** 질문 규칙(v2.1 규칙 13, 한 질문에 한 주제) 확인 결과, 질문 쓰기 규칙 몇 가지 예시
- 출처: `docs/질문루프_정리.md` 3절, `docs/상세환자_질문루프_기록_10-18.md`

### 6. 판정 기준 만들기와 정확도: 82.7% → 93.1% → 99.4%
- **말할 것**
  - 사람이 직접 판정한 정답(평가 세트)을 먼저 만들었어요. 환자 9명, 시험 15개, 기준 173개, 두 사람 판정 일치도 93%예요.
  - AI가 틀린 기준을 유형별로 분석해서 규칙을 고쳤어요.
- **보여 줄 것**: 막대그래프
  | 버전 | 기준 일치 | 최종 판단 |
  |---|---|---|
  | v1 (팀 규칙 전) | 143/173 (82.7%) | 13/15 |
  | v2 (팀 회의 결정 반영) | 161/173 (93.1%) | 15/15 |
  | **v3 (유형별 분석 반영)** | **172/173 (99.4%)** | **15/15** |
- 고친 유형 예: 추정 진단을 사실처럼 씀(5건), 기록에 없는 검사 수치를 잘못 분류(3건)
- 모델을 **약 2.5배 저렴한 Sonnet 5.5**로 바꾸면서도 정확도가 올랐어요. 평가 1회 $0.13
- **꼭 같이 말할 것**: 이 99.4%는 규칙을 만들 때 본 데이터라 독립 검증이 아니에요. 그래서 다음 장의 새 환자 검증을 했어요.
- 출처: `eval/결과_4차_판정v3_Sonnet.md`

### 7. 새 환자 검증: 정보가 있으면 다 맞힌다 (20/20)
- **말할 것**: 인선이 짧은 환자 설명에 검사 수치, 병력, 복용약을 덧붙인 "상세 환자"를 만들고 직접 판정했어요. 판정 규칙을 만들 때 보지 않은 데이터예요.
- **보여 줄 것**
  | | 결과 |
  |---|---|
  | 환자 / 시험 / 기준 | 2명 (S004 방광암 의심, S008 폐섬유증) / 4개 / 46개 |
  | 정답이 통과·탈락인 기준 | **20/20** |
  | 기준 일치 (모름·등록 후 확인 포함) | 43/46 |
  | 최종 판단 | 4/4 |
- 평가 세트는 정답의 71%가 "모름"이라 통과·탈락 정확도를 거의 못 쟀는데, 이번에 처음 쟀다는 점을 강조해요.
- 틀린 3개는 모두 "AI가 명시되지 않은 걸 추론해서 통과"예요(10장 한계에서 다룸).
- **[빈칸: 인선]** 바뀐 판정에 대한 의견, 상세 환자 만들면서 어려웠던 점 (예: 의학 지식, 판정이 한쪽으로 쏠릴 위험)
- 출처: `docs/10-18_주희_상세환자_작업정리.md`

### 8. 질문 루프: 정보가 없으면 질문으로 되찾는다 (5 → 17)
- **말할 것**: 1위 팀처럼 평가했어요. 상세 환자의 정보를 가리고 짧은 설명에서 시작해서, AI가 질문하고 답을 받은 뒤 다시 판정해요. 그리고 상세 환자 정답과 비교해요.
- **보여 줄 것**
  | | 질문 전 | 질문 후 |
  |---|---|---|
  | 정답이 통과·탈락인 기준 | 5/20 | **17/20** |
  | 기준 일치 | 31/46 | **41/46** |
  | 모름 개수 | 36 | 22 |
  | AI가 만든 질문 | | 21개 (최대 3라운드, 라운드당 5개) |
- 모름이 22개 남은 건 상세 설명에도 없는 정보라서, 환자가 "모르겠어요"라고 답했기 때문이에요. AI가 없는 정보를 지어내지 않았다는 뜻이에요.
- 대표 장면: 5장의 S008 Q2, S008 Q5 "헤모글로빈 보정 확산능력 42%" → 폐기능 기준 통과
- 출처: `docs/상세환자_질문루프_기록_10-18.md` (질문 21개와 답, 바뀐 판정 전부)

### 9. 시험하다 배운 것: 환자 역할 AI도 검증해야 한다
- **말할 것**: 질문에 답하는 "환자"도 AI(시뮬레이터)가 맡았어요. 처음에는 설명에 없는 "아니요"를 지어내서, 결과가 실제보다 좋아 보였어요. 그래서 고치고 다시 돌렸어요.
- **보여 줄 것**: 전후 비교
  | 질문 | 고치기 전 | 고친 뒤 |
  |---|---|---|
  | 방광·신장·전립선암 병력 | "그런 말을 들은 적은 없어요" (설명에 없는 내용) | "그건 기억이 잘 안 나요" |
  | 스테로이드·면역억제제 | "안 먹어요" (설명에 없는 내용) | "잘 모르겠어요" |
- 고치기 전에는 모름이 36 → 15로 줄었지만 믿을 수 없는 숫자였어요. 고친 뒤 36 → 22가 진짜 숫자예요.
- 정직하게 검증한 과정을 보여 주는 장면이라 정성 평가에 좋아요.
- 출처: `docs/상세환자_질문루프_기록_10-18.md` "시뮬레이터를 고치기 전과 비교"

### 11. 한계 (정직하게)
- 상세 환자가 **2명, 기준 46개**라 작아요.
- 질문 루프의 답은 사람이 아니라 **시뮬레이터**가 했어요.

## 예상 질문과 답 (Q&A 대비)

| 질문 | 답 |
|---|---|
| 99.4%는 같은 데이터로 규칙을 고친 거라 과적합 아닌가요? | 맞아요. 그래서 처음 보는 상세 환자로 다시 검증했고, 통과·탈락 20/20이었어요. 다만 2명이라 더 늘릴 계획이에요 |
| 1위 팀(기준 판정 79.1%)보다 높은데 비교할 수 있나요? | 데이터와 정답 기준이 달라서 직접 비교는 어려워요. 우리 평가 세트는 정답의 71%가 모름이라 쉬운 편일 수 있어요. 그래서 통과·탈락만 따로 잰 숫자(20/20)를 같이 보여 줘요 |
| 시뮬레이터 답을 믿을 수 있나요? | 상세 설명에 있는 것만 답하게 했고, 지어낸 답을 발견해서 고쳤어요(9장). 데모에서는 사람이 직접 답했어요 |
| 비용은 얼마나 드나요? | 평가 세트 전체 판정 1회 $0.13(배치 할인). 상세 환자 2명 질문 루프 $0.40 |
| AI가 틀린 판정을 내면 위험하지 않나요? | 추천 순위는 코드 규칙으로 정하고, 확실한 기준(나이·임신)은 코드가 판정해요. 화면에 "의학적 자문이 아닌 참고용" 문구가 있어요 |
| "등록 후 확인"은 왜 따로 두나요? | 동의서나 연구자 판단은 환자에게 물어도 답이 없어요. 모름과 섞으면 쓸데없는 질문이 늘어요 |

## 발표 전 체크
- [ ] 발표 시간과 장표 수 확인
- [ ] 1위 팀 수치(79.1% 등) 인용 범위 확인: 연구실 참고 자료라 원본은 공유하지 않기로 했어요. 발표에서 수치를 말해도 되는지 확인이 필요해요
- [ ] 데모 영상: 새 질문 화면으로 다시 녹화할지
- [ ] 팀원 결과 반영 후 숫자 다시 확인 (정답이 바뀌면 숫자도 바뀜)
