### ⑧ 5번 → 6번 연결 형식 결정 (10/15)
- **왜**: 기존 방식에는 문제가 4가지 있었어요.
  1. 답변을 받으면 AI가 프로필 전체를 새로 써서, 정보가 빠지거나 바뀌어도 알 수 없었어요
  2. 답 하나에 **모든 시험의 모든 기준**을 다시 판정했어요 (비용 낭비)
  3. 데모(`app.py`)와 실험 스크립트가 파이프라인을 각자 다시 구현해서, 평가한 코드와 시연하는 코드가 달라질 수 있었어요
  4. AI 판정 결과를 검사하지 않았어요
- **결정**
  - 질문·답변·바뀐 판정은 **handoff 파일 하나에 라운드별로(`rounds`)** 쌓아요
  - 5번은 파일을 건드리지 않는 함수 `build_questions(bundle)`로 만들어요 (해준님)
  - 질문 ID는 Q1, Q2, … 라운드를 넘어 통번호로 붙여요
  - 판정에는 프로필을 다시 쓰지 않고, 원문과 답변을 직접 넘겨요
- **위치**: `docs/질문루프_정리.md`

### ⑨ 판정 출력 검사 — 안전장치 (10/15)
- **무엇**: AI가 기준을 빠뜨리거나, 이상한 판정값을 내거나, 같은 기준을 두 번 내면 코드가 바로잡아요. 빠진 기준은 "모름"으로 채워요.
- **왜 중요한가**: 탈락 기준 하나를 AI가 빠뜨리면, 나머지가 다 통과일 때 최종 판단이 "적격 가능"으로 잘못 나와요. 검사 후에는 "정보 부족"이 되어 질문으로 확인하게 돼요.
- **결과**: 저장된 실제 판정 결과(v1·v2·v3)에서는 고칠 게 0건이었어요 (지금은 문제가 없지만, 생기면 막아 줘요).

### ⑩ 6번 재평가 완성 (10/15 ~ 10/16)
- **흐름**

```
[1~4] 첫 판정 → [5] 질문 (next_round) → 환자 답변 → [6] 관련 기준만 재판정 (reassess) → [5] … 반복
→ 질문을 마치면 전체 재판정 한 번 (final_check) → [7] 추천
```

| 함수 | 하는 일 |
|---|---|
| `next_round(bundle)` | 질문을 만들어 `rounds`에 기록. 부적격 시험, 이미 물어본 기준은 뺌 |
| `reassess(bundle, answers)` | 답변을 기록하고 **답과 관련된 기준만** 다시 판정. 바뀐 판정을 근거 질문과 함께 기록 |
| `final_check(bundle)` | 모든 기준을 원문 + 모든 답변으로 다시 판정 (부분 재판정이 놓친 것 바로잡기) |

- 답변이 없을 때는 v3 평가 때와 **똑같은 요청**이 나가서, 172/173 결과가 그대로 유효해요.
- 무료 점검(가짜 AI)을 모두 통과했어요: `scripts/check_reassess.py`

### ⑪ 질문 루프 첫 실제 실행 (10/16, S004 방광암 의심 환자)

| 시험 | 시작 | 2라운드 후 | 전체 재판정 후 |
|---|---|---|---|
| NCT04369560 (MRI 연구) | 정보 부족, 모름 9 | 부적격 (잘못된 탈락) | 정보 부족, 모름 9 |
| NCT05646485 (혈뇨 검진) | 정보 부족, 모름 4 | 정보 부족, **모름 1** | 그대로 |

- **잘 된 점**
  - 질문이 자연스러워요: "페루목시톨" → "철분 주사"로 풀어서 물음
  - 답 하나로 판정이 바뀌고 근거에 답변이 인용돼요: "하루 한 갑씩 45년" → 45갑년이라 흡연 기준 통과
  - "잘 모르겠어요"라는 답은 억지로 통과시키지 않고 모름으로 둬요
- **찾은 문제와 처리**

| 문제 | 처리 |
|---|---|
| 같은 답("조직검사 아직, 수술 일정 없음")을 부분 재판정은 **탈락**, 전체 재판정은 **모름**으로 판정 (정답: 모름). 잘못된 탈락 하나로 그 시험에는 다음 라운드 질문을 안 함 | 질문을 마치면 전체 재판정을 **항상** 하도록 바꿈 |
| 1라운드 질문 5개가 전부 한 시험 것 | 시험별로 번갈아 고르게 고침. 해준님 `build_questions()`에도 같은 요구 |
| "흡연 15갑년 **또는** 직업 노출 15년"을 둘 다 맞아야 하는 것처럼 계산 | **미해결** (아래 "막힌 것") |

- 비용: 약 $0.1~0.2. 이제 일반 호출 비용도 자동으로 기록해서 실행 끝에 보여 줘요.

### ⑫ 인선님 상세 환자 검증 준비 (10/17)
- **왜**: 99.4%가 독립 검증이 아니라서, 규칙을 만들 때 보지 않은 새 환자로 다시 재야 해요.
- **무엇**
  - **시트 점검 (무료)**: 시트를 읽어서 빈 판정, 이상한 값, 평가 세트와 다른 기준 ID, 인선님이 적은 최종 판단이 기준별 판정으로 계산한 값과 다른지 알려 줘요
  - **A. 정보가 다 있을 때**: 상세 설명으로 바로 판정 → 인선님 정답과 비교. 핵심 숫자는 "정답이 통과·탈락인 기준을 몇 개 맞혔나"
  - **B. 1위 팀 방식**: 짧은 원래 설명에서 시작 → 질문 → 시뮬레이터가 상세 설명만 보고 답변 → 재판정. 질문 전·후로 정답과 얼마나 가까워졌는지 비교
- **예상 비용**: 환자 1명당 A 약 $0.03~0.06, B 약 $0.1~0.3 (실행 전 확인 후 진행)
- **위치**: `scripts/eval_detailed.py`, `src/testing/detailed_sheet.py`

- **새 환자 검증** (인선님 상세 환자): A·B 숫자를 발표의 두 번째 핵심 숫자로

- **발표 자료** (인선님과): 판정 정확도 변화 표, 질문 하나로 판정이 바뀌는 장면, 한계를 솔직하게
  - 발표 문구 제안: "틀린 판정을 유형별로 분석해 규칙을 고쳤더니 93% → 99%가 됐다. 새 환자로 추가 검증 중이다."

### 발표 후
- "또는" 기준 처리
- 수치·날짜 계산 도구를 판정에 연결
- 질문 루프 평가: 질문 몇 개로 모름이 몇 개 줄었나
- 7번 추천 다듬기
- 제출물 체크리스트: 에이전트 구성도, README, 데이터 출처·라이선스, 의료 면책 고지
- 보류한 것: 약물 사전 (새 환자 검증에서 약 이름 오류가 실제로 나오면 다시 검토)
