# 판정 프롬프트 비교 실험 (인선 · 대조군 해준)

> 10/26 중간발표 피드백: "에이전트를 강화하기보다, **어떤 프롬프트를 넣었을 때 성능이 구체적으로 어떻게 변했는지** 확실하게 검증하라."
> 지금 근거(82.7 → 99.4%)는 ① 같은 평가 세트를 보면서 고친 결과이고 ② v3에서 모델도 Opus → Sonnet으로 바뀌어서, 프롬프트 효과만 따로 말할 수 없어요. 이 실험은 **모델과 입력을 고정하고 판정 프롬프트만 바꿔서** 그 효과를 재요.

## 무엇을 비교하나

| 조건 | 파일 | 내용 | 무엇을 보나 |
|---|---|---|---|
| p0 | `prompts/p0.txt` | 규칙 없음 (판정 4단계 정의 + 출력 형식만) | 출발점 |
| p1 | `prompts/p1.txt` | + 사전 실험(수동 스크리닝 ①)에서 나온 규칙 7개 | 사전 실험 효과 |
| p2 | `prompts/p2.txt` | + 평가 세트 팀 결정(수동 스크리닝 ②): 등록 후 확인 범위, 기록에 없는 수치 = 모름 | 팀 결정 효과 |
| v3 | 코드 (`src/agents/matcher.py`의 `SYSTEM_PROMPT`) | + 오류 분석 규칙: 추정 진단 사용 금지, 수술 적합성, 영아 예시 | 오류 분석 효과 (지금 쓰는 프롬프트) |
| v3_r1112 | v3 + `prompts/_rules_11_12.txt` | + 규칙 11·12 (10/18 보류) | 보류한 규칙을 넣을지 |
| control | `prompts/control.txt` (**해준님이 만들 파일**) | 사람이 만든 규칙 대신 **AI가 스스로 쓴 판정 지침** | 수동 스크리닝 자체의 효과 |

- 규칙 외의 문장(역할, 판정 4단계 정의, 출력 형식)은 모든 조건에서 똑같아요. **규칙 부분만 달라요.**
- 모든 조건에 같은 입력을 줘요: 환자 원문 + 프로필 + 기준. 그래서 예전 v1·v2 숫자(프로필만 입력, Opus)와는 다를 수 있어요.
- 데이터는 **따로** 채점해요.
  - **평가 세트** (기준 173개): 규칙을 고칠 때 본 데이터예요. 정답이 통과·탈락인 기준은 23개뿐이에요.
  - **상세 환자**: 규칙을 고칠 때 안 본 상세 정보예요. 모든 기준에 판정이 채워진 시트만 자동으로 써요(판정 중인 시트는 빠짐).

## ⚠️ 실행 전에 꼭 지킬 것
1. **p1·p2 규칙 구분 확인 (인선님)**: 어떤 규칙이 사전 실험에서 나왔고 어떤 게 팀 결정인지는 주희(Claude)가 기록을 보고 나눈 거예요. 판정 개발 과정을 제일 잘 아는 인선님이 `prompts/p1.txt`, `p2.txt`를 보고 맞는지 확인해 주세요. 고칠 거면 **실행 전에** 고치고, 그다음엔 고정해요.
2. **결과를 보고 프롬프트를 고치지 않기**: 고치면 다시 "같은 데이터를 보고 만든 규칙"이 돼요. 고치고 싶으면 새 조건 파일(예: `p3_new.txt`)로 추가하고, 그렇게 했다고 기록해 주세요.
3. **상세 환자 정답이 먼저**: 새 상세 환자(S002·S010·N001·N002)는 판정이 끝나기 전에 AI 결과를 보면 안 돼요. 평가 세트로 먼저 돌리고, 상세 환자 판정이 끝나면 그때 다시 돌리면 돼요(이미 돈 것은 재사용).
4. **비용**: 실행 전에 `--dry-run`으로 예상 비용을 확인하고 **주희에게 알린 뒤** 돌려요. API 키는 연구실 공용 키라 단톡방·GitHub에 올리지 않아요. 키 파일은 프로젝트 루트 `.env`에 `ANTHROPIC_API_KEY=...` 한 줄이에요(주희에게 개인적으로 받기).

## 대조군 만들기 (해준님)
- 목표: "수동 스크리닝 없이, AI에게 판정 지침을 쓰게 하면 어떤가?"
- 방법 (제안): 새 대화에서 AI에게 **과제 설명, 판정 4단계 정의, 출력 형식만** 주고 "판정 규칙을 써 달라"고 해요. **우리 규칙(p1~v3)이나 평가 세트·상세 환자 내용은 보여 주지 않아요.**
- 받은 규칙을 `prompts/p0.txt`의 `Verdicts` 부분과 `Respond with ONLY` 사이에 `Judgment rules (follow strictly):`로 넣어 `prompts/control.txt`로 저장해요. 그러면 자동으로 `control` 조건이 생겨요.
- AI에게 준 요청 문장과 받은 답을 그대로 `prompts/_control_생성기록.md`에 남겨 주세요(재현용).

## 실행 방법
프로젝트 폴더에서 (Windows는 한글 출력 때문에 앞에 `PYTHONIOENCODING=utf-8`을 붙이면 좋아요):

```bash
python scripts/ablation_judge.py --dry-run                         # 무료: 할 일과 예상 비용
python scripts/ablation_judge.py --datasets goldset                # 평가 세트만, 모든 조건 × 3회
python scripts/ablation_judge.py                                   # 평가 세트 + 상세 환자
python scripts/ablation_judge.py --conditions control --repeats 3  # 대조군만 추가로
python scripts/ablation_judge.py --report                          # 무료: 저장된 결과만 다시 채점
```

- 기본은 **배치 API**(비용 50% 할인)라 몇 분~1시간 기다려요. 바로 보고 싶으면 `--no-batch`(정가).
- 같은 조건·회차는 저장된 결과를 다시 써요. 중간에 끊기면 그냥 다시 실행하면 남은 것만 돌아요.
- 예상 비용 (10/28 기준): 평가 세트만 5개 조건 × 3회 약 **$2**, 상세 환자 2명 포함 약 **$2.4**. 새 상세 환자 4명이 추가되면 약 $1~2 더 들어요.

## 결과 읽기
`data/processed/judge_ablation/`
- `summary.md`: 조건 × 데이터별 점수표
  - **기준 일치 (AI만)**: 프롬프트 효과만 본 점수 → 실험의 주 숫자
  - **기준 일치 (+코드)**: 나이·임신 코드 판정과 출력 검사를 더한 점수 (파이프라인과 같은 방식)
  - **통과·탈락**: 정답이 통과나 탈락인 기준만. 평가 세트는 모름이 71%라 전체 일치율이 부풀려져서 이걸 따로 봐요
  - **흔들린 기준**: 3번 돌렸을 때 판정이 회차마다 달랐던 기준 수. 이게 크면 조건 차이가 우연일 수 있어요
  - 맨 아래: 이웃한 조건끼리(p0 → p1 → p2 → v3 → v3_r1112) **고쳐진 / 망가진** 기준 수
- `changes.csv`: 조건이 바뀔 때 다수결 판정이 바뀐 기준 목록 → **오류 분석은 이 파일로 해요**
- `criteria.csv`: 모든 조건·회차·기준의 판정과 AI 근거

## 오류 분석 (발표에 쓸 핵심)
연구원분이 원한 건 "몇 % 올랐다"보다 **"어떤 규칙이 어떤 오류를 고쳤나"**예요.
1. `changes.csv`에서 `from`·`to`별로 "고쳐짐", "망가짐" 기준을 봐요.
2. 각 기준의 AI 근거(`criteria.csv`)를 보고 **왜 바뀌었는지 유형을 붙여요.** 예: "p1 → p2에서 고쳐진 9개 중 6개는 동의서·연구자 판단 기준 → 팀 결정 1·4번 효과"
3. "흔들린 기준"에 들어간 기준이 바뀐 거라면 규칙 효과가 아니라 원래 흔들림일 수 있다고 표시해요.
4. 정리 결과는 `docs/`에 문서로 남겨 주세요.
