# 04. 질문 평가 루브릭

**연구자용 문서이다. 평가자에게 배포하지 않는다.** 조건 구성과 가설이 들어 있기 때문이다. 평가자에게는 `04_annotation_guideline.md`와 `04_error_taxonomy.md`만 제공한다.

| 항목 | 내용 |
|---|---|
| 지표 코드 | `evaluation/scoring.py`의 `set_metrics`, `stability`, `verdict_flip_rate`, `m8_metrics` |
| 코드값 | `evaluation/scoring_schema.json` |
| 우선순위 | 지표 정의는 이 문서가 `02_experiment_design.md` 4절보다 우선한다. |

---

## 1. 세 평가 축

| 축 | 질문 | 지표 | 평가 시점 | 정답 필요 |
|---|---|---|---|---|
| Faithfulness (원문 충실성) | 기준을 왜곡하거나 근거 없는 사실을 전제하지 않는가? | M1, M2, M5, M6 | 질문 생성 후 | 아니오 |
| Coverage (정보 커버리지) | 기존 정보로 판단할 수 없는 기준을 실제로 확인하는가? | M3, M4 | 질문 생성 후 | 아니오 |
| Utility (실질적 유용성) | 답변 후 불확실성이 줄고 판정이 올바르게 개선되는가? | M3d(구조적 대리값), M8 | M8은 재판정 후 | M8만 |

M7은 세 축의 측정값이 반복 실행에서 얼마나 안정적인지를 본다.

### 평가 단위

| 단위 | 정의 | 채점표 |
|---|---|---|
| 세트 | 실행 1회의 `arrange` 후 질문 전체. blind_id 1개. | |
| 질문 | 세트 안의 질문 1개 | `question_sheet` |
| 연결 | `resolves`를 전개한 (질문, 시험, 기준) 1건 | `link_sheet` |
| 기준 | 환자의 시험·기준 1건. 세트 안에서 중복을 제거한 단위 | 계산 |

### 공통 기호

| 기호 | 정의 |
|---|---|
| Q, L | 세트의 최종 질문 집합, 연결 집합 |
| U | 질문 후보. S004 13개, S008 23개 |
| Uv | U 중 사전 주석에서 NOT_OBTAINABLE이 아닌 기준 |
| H | Uv 중 고영향 기준. 주 분석은 `h_strict`, 민감도는 `h_any` |
| Sub | 연결 중 coverage가 FULL 또는 PARTIAL인 고유 기준 |
| Full | 연결 중 coverage가 FULL인 고유 기준 |

### 공통 값 처리

| 값 | 의미 | 계산 |
|---|---|---|
| PASS / FAIL | 판단 완료 | 분모에 포함 |
| UNSURE | 판단 불가 (사유 필수) | 분모에서 제외, 건수와 비율 보고 |
| NA | 해당 없음 | 분모에서 제외 |
| 빈 값 | 미채점 | 검증 실패. 계산 전에 해소한다. |
| 분모 0 | | 값 없음(None). 0으로 채우지 않는다. |
| 실패한 실행 | 세트 없음 | 평균에서 제외하고 건수 보고. 0점 처리하지 않는다. |

UNSURE 비율이 지표별 20%를 넘으면 해당 값을 불안정으로 표시한다.

### 집계

세트 값 → 환자×조건의 평균과 범위(반복 3회) 순서로 집계한다. 환자를 합산하지 않으며, 반복을 표본으로 세지 않는다.

## 2. 지표 정의

### M1. 원문 조건 보존

- **정의:** 질문이 다룬 조건이 기준 원문의 의미와 같은가. 기간·기준 시점, 수치, 단위, 빈도, 진단, 약물, 용량, 투여 경로, AND/OR, 예외, 원인 관계, 적용 대상을 본다.
- **단위:** 연결. 질문 문장을 기준으로 판단한다. `needed_info`는 질문의 목적을 파악하는 데만 쓴다.

| ID | 계산식 | 분모 |
|---|---|---|
| `M1a` | 1 − FAIL 연결 / 평가 가능 연결 | preservation이 PASS·FAIL인 연결 |
| `M1b` | 1 − FAIL 연결이 있는 질문 / 평가 가능 질문 | 평가 가능 연결이 1개 이상인 질문 |
| `M1c` | coverage=PARTIAL 연결 / 평가 가능 연결 | 위와 같음 |

| 판정 | 기준 |
|---|---|
| PASS | 질문이 다룬 조건이 원문과 같은 의미이다. 원문 조건을 전부 담지 않아도 된다. |
| FAIL | 다룬 조건을 바꾸거나, 넓히거나, 좁히거나, 원문에 없는 조건을 더했다. F 코드 필수. |
| UNSURE | 원문 자체가 모호하거나 번역 등가성을 판단할 수 없다. |
| NA | coverage=NONE. 질문이 그 기준을 다루지 않으므로 왜곡을 판단할 대상이 없다. |

- **부분 충족:** 언급하지 않은 조건은 FAIL이 아니라 부분 커버(M3)이다. 예를 들어 "A 또는 B" 중 A만 물으면 PASS + PARTIAL이고, "A"로 범위를 바꾸어 답을 B까지 포함한 것처럼 처리하면 FAIL이다.
- **복합 질문:** 연결마다 따로 판단한다. 한 연결의 FAIL은 다른 연결에 전파되지 않는다.
- **보호 장치:** 다기준 질문이 많은 세트는 연결 수가 많아 FAIL 기회도 많다. M1a와 M1b를 함께 보고한다.
- **`needed_info`만 왜곡:** FAIL로 세지 않고 `other_error`에 기록한다. 환자와 판정기에 전달되지 않기 때문이다.
- **자동화:** 불가. 사람이 판단한다. 숫자·기간 표현 추출은 채점 보조로만 쓸 수 있다.

### M2. 근거 없는 가정

- **정의:** 질문이 입력 정보에 없는 진단·치료·검사·상태를 사실로 전제하는가.
- **판단 기준:** **짧은 환자 설명(입력)만** 사용한다. 상세 설명에서 사실이어도 입력에 없으면 가정이다.
- **단위:** 질문.

| ID | 계산식 | 분모 |
|---|---|---|
| `M2` | FAIL 질문 / 평가 가능 질문 | assumption이 PASS·FAIL인 질문 |

| 판정 | 기준 |
|---|---|
| PASS | 전제가 없거나 입력에 근거가 있다. "~한 적이 있나요?" 같은 중립 확인은 PASS이다. "받으셨다면"처럼 조건부로 묻는 것도 PASS이다. |
| FAIL | 일어났다고 전제한다. A 코드 필수. |
| UNSURE | 표현이 전제인지 조건부인지 불명확하다. |

- **복합 질문:** 일부에 전제가 있으면 질문 전체가 FAIL이다.
- **자동화:** 불가.

### M3. 유효 미확인 기준 커버리지

- **정의:** 입력만으로 판단할 수 없고 확보 가능한 기준 중, 질문이 실제로 확인하는 기준의 비율.
- **단위:** 기준 (연결에서 판정).

| ID | 계산식 | 분모 | 의미 |
|---|---|---|---|
| `M3a` | \|연결된 고유 기준 ∩ Uv\| / \|Uv\| | Uv | 연결 커버리지. 자동 계산. 진단용. |
| `M3b` | \|Sub ∩ Uv\| / \|Uv\| | Uv | 실질 커버리지 (주 지표) |
| `M3c` | \|Full ∩ Uv\| / \|Uv\| | Uv | 완전 커버리지 |
| `M3d` | \|Sub ∩ Uv\| / \|Q\| | Q | 질문당 실질 커버 (RQ3 주 지표) |

| coverage | 기준 |
|---|---|
| FULL | 답변을 받으면 그 기준의 판정에 필요한 정보가 모두 수집된다. |
| PARTIAL | 일부 조건만 수집된다. C2·C3·G5 중 하나 필수. |
| NONE | 질문이 그 기준을 확인하지 못한다. C1 필수. |
| UNSURE | 필요한 정보의 범위를 판단할 수 없다. |

- **기록 요청:** 내용을 특정해 제공을 요청하면(예: "크레아티닌이 있는 결과지를 제공해 주실 수 있나요?") FULL일 수 있다. 보유 여부만 물으면 PARTIAL + C3이다. 이 규칙은 수치를 기억으로 묻지 않는 프롬프트가 불리해지지 않게 한다.
- **기억으로 수치 요구:** 정보는 요청되므로 coverage는 FULL일 수 있다. 대신 `other_error`에 U1을 기록한다.
- **여러 질문에 나뉜 경우:** 한 질문이라도 FULL이어야 완전 커버이다. 합쳐서 완전해지는지는 판단하지 않는다.
- **연결이 없는 기준:** 커버되지 않은 것으로 센다. 질문이 사실상 다루어도 `resolves`에 없으면 채점 대상이 아니다. 채점자는 `other_error`로 표시할 수 있다.
- **이미 해결된 정보:** 입력에 있는 내용만 다시 물으면 NONE + C1이고, 질문 단위에 R2를 기록한다.
- **자동화:** M3a는 자동, coverage 판정은 사람.

### M4. 고영향 기준 커버리지

- **정의:** 사전 주석의 고영향 기준이 5개 질문 안에 실제로 포함되는가.
- **상태: 잠정 확정.** 고영향 정의는 팀 검토 전 최종 실험에 쓰지 않는다. 검토 완료는 사전 주석 잠금의 조건이다.
- **단위:** 기준. M4b만 세트.

| ID | 계산식 | 분모 | 역할 |
|---|---|---|---|
| `M4a` | \|Sub ∩ H\| / \|H\| | H (`h_strict`) | RQ2 주 지표. `h_any` 값도 병기. |
| `M4b` | 1~2번 질문의 \|Sub ∩ H\| / 전체 \|Sub ∩ H\| | 커버된 H | 순서 보조 지표 |
| `M4c` | 시험별 \|Sub\| | 없음 | 기술 통계 |

- **Pass/Fail:** 기준별 값은 M3의 coverage를 따른다. 이 지표에 별도 판정 항목은 없다.
- **N/A:** H가 비면 값 없음. \|H\|를 항상 함께 보고한다.
- **순서 해석:** 단일 라운드에서 순서는 절단이 일어날 때만 수집 결과를 바꾼다. M4b는 성과가 아니라 경향이다.
- **자동화:** 계산은 자동. 입력(사전 주석, coverage)은 사람.

### M5. 묶기 정확성

- **정의:** 한 질문이 여러 기준을 확인할 때 각 기준의 필요한 정보가 보존되는가.
- **단위:** 다기준 질문의 연결. M5b만 공유정보 군집.

| ID | 계산식 | 분모 |
|---|---|---|
| `M5a` | VALID 연결 / 평가 가능한 다기준 연결 | group_validity가 VALID·INVALID |
| `M5b` | 한 질문에서 함께 커버된 군집 / 2개 이상 커버된 군집 | 공유정보 군집 |
| `M5c` | preservation=PASS이고 coverage=FULL인 연결 / 다기준 연결 | UNSURE 제외, 허위 연결 포함 |

| group_validity | 기준 |
|---|---|
| VALID | 하나의 답변이 이 기준에 필요한 같은 사실을 제공한다. |
| INVALID | 답변이 이 기준에 쓰이는 사실이 아니거나, 다른 사실과 구분할 수 없다. 허위 연결은 항상 INVALID이다. |
| UNSURE | 판단 불가 |
| NA | 기준 1개만 연결된 질문 |

- **부분 충족:** PARTIAL이어도 같은 사실이면 VALID일 수 있다. 묶기 과정에서 조건이 빠지면 G5를 기록한다.
- **N/A:** 다기준 질문이 없으면 값 없음. S004는 값이 없을 가능성이 높다.
- **자동화:** 다기준 여부와 M5b 계산은 자동, 판정은 사람.

### M6. 과잉 묶기 및 불필요한 중복

- **정의:** 다른 조건을 무리하게 결합하거나 같은 정보를 불필요하게 반복하는가.
- **단위:** 질문.

| ID | 계산식 | 분모 | 판정 항목 |
|---|---|---|---|
| `M6a` | overgroup=FAIL 질문 / 평가 가능한 다기준 질문 | PASS·FAIL | 과잉 묶기 |
| `M6b` | redundancy=FAIL 질문 / 평가 가능 질문 | PASS·FAIL | 불필요한 중복 |
| `M6c` | single_topic=FAIL 질문 / 평가 가능 질문 | PASS·FAIL | 주제 단일성 |

| 항목 | PASS | FAIL |
|---|---|---|
| overgroup | 묶인 기준이 같은 사실을 묻는다. | 서로 다른 사실·기간·대상·측정값을 합쳤다. G 코드 필수. 기준 1개 질문은 NA. |
| redundancy | 새로운 정보를 묻는다. 다른 기준을 정확히 판정하기 위한 반복은 PASS이다. | 세트 안 동일 정보 반복(R1, duplicate_of 필수) 또는 입력에 있는 정보 재질문(R2). |
| single_topic | 한 사실이나 그 직접 후속 정보를 묻는다. | 독립된 사실을 한 번호에 넣었다. T1. |

- **자동화:** 동일 기준 중복의 일부는 `arrange`가 제거한다. 원시 출력의 중복은 D3으로 자동 집계한다. 의미 판단은 사람.

### M7. 반복 안정성

- **단위:** 환자×조건.

| ID | 계산식 | 분모 | 처리 |
|---|---|---|---|
| `M7a` | 3쌍의 Sub 기준 집합 Jaccard 평균 | 쌍 3개 | 양쪽 공집합인 쌍은 제외 |
| `M7b` | 반복 간 최종 판정이 다른 기준 / 전체 기준 | 기준 | 재판정한 조건만 |

M1~M6의 반복 범위도 함께 보고한다. 질문 문장의 표면적 차이는 지표로 쓰지 않는다. 안정성이 높다고 품질이 높은 것은 아니다. 같은 오류를 반복할 수도 있다. 자동 계산이지만 M7a의 입력은 사람의 coverage 판정이다.

### M8. 후속 판정 개선 (보조)

**정답이 필요하다. 채점 잠금 후에만 계산한다.** 재판정 실행은 잠금 전에 해도 되지만 결과는 열지 않는다. A2s는 계산하지 않는다.

| ID | 계산식 | 분모 |
|---|---|---|
| `M8a` | 정답과 일치하게 확정된 기준 / 정답이 통과·탈락인 후보 | S004 6, S008 9 |
| `M8b` | 통과·탈락이 된 후보 / 정답이 모름인 후보 (과잉 확정) | S004 7, S008 14 |
| `M8c` | M8a의 건수 / \|Q\| | Q |
| `M8d` | 틀어진 기준 / 초기에 정답과 일치한 비후보 기준 (회귀) | S004 6, S008 4 |
| `M8e` | 시험별 최종 판단 일치 | 사례 보고, 시험 4개 |

- `reassess` 직후와 `final_check` 직후를 각각 계산하고, 대상 기준과 전체 기준을 분리한다.
- `unknown → post_enrollment`는 해소가 아니며 따로 센다.
- fail→pass는 정답 탈락이 1개뿐이므로 사례로만 보고한다.
- 시뮬레이터 응답 코드가 S1·S2·S3인 답변을 뺀 민감도 값을 함께 보고한다.
- 자동 계산. 시뮬레이터 응답 코드만 사람이 판단한다.

---

## 3. 진단 지표

성과로 비교하지 않는다. 실행 로그에서 자동 계산한다.

| ID | 내용 |
|---|---|
| D1 | 최종 질문 수 |
| D2 | 원시 질문 수, 절단된 질문 수 |
| D3 | `arrange` 제거 건수·사유, 원시 출력의 동일 기준 중복 |
| D4 | 질문당 연결 수, 다중 시험 질문 수 |
| D5 | JSON 실패, 재시도, `stop_reason` |
| D6 | `not_asked` 완전성, `resolves`와의 모순, 사유 유효성 |
| D7 | 토큰, 비용, 시간, 프롬프트 길이 |
| D8 | 시뮬레이터 응답 코드 분포 |
| `D9` | 질문별 한글 비율, 언어 이탈 건수 (4절) |

`remaining_info`는 어떤 지표의 필수 입력도 아니다. `not_asked`는 C0에 완전성 지시가 없으므로 조건 간 성과 비교에 쓰지 않는다.

## 4. 출력 언어 통제

**문제:** C0에만 "한국어로"가 있다. C_full에는 해당 문구가 없다.

| 방안 | 내용 | 판단 |
|---|---|---|
| A | 프롬프트를 유지하고 언어를 자동 점검 | **채택** |
| B | C0에서 문구 제거 | 프롬프트 재생성 필요. 지시에 따라 하지 않는다. C0만 영어 출력 위험이 커진다. |
| C | 전 조건에 "한국어로" 추가 | C_full이 실행판 원문이 아니게 되어 불가 |
| D | 전 조건의 사용자 메시지에 공통 문구 추가 | 프롬프트 해시는 유지되나 `question_input`과 달라져 파이프라인 입력이 바뀐다. 불채택. |

**근거:** 저장된 v2.3.3 질문 47개의 한글 비율은 중앙값 1.00, 최솟값 0.556이다. 프롬프트가 한국어로 작성되어 있어 출력도 한국어로 나온 것으로 보인다. 단, A1·A2·A2s의 출력은 아직 관측되지 않았다.

**사전 규칙:**

1. `D9` = 한글 / (한글 + 라틴 문자). 0.5 미만이면 언어 이탈로 표시한다.
2. 언어 이탈은 재생성 사유가 아니다. 그대로 저장하고 채점한다.
3. 조건별 이탈 건수를 보고한다. 이탈이 발생한 조건은 RQ 해석에 언어 차이를 교란 요인으로 명시한다.
4. 프로토콜 수정이 필요할 정도면 새 프롬프트 버전을 별도 조건으로 만들고, 파일럿 결과를 개발 결과로 재분류한다.

## 5. 지표 간 중복

## 8. STEP 5 구현 요구사항

1. 실행 기록을 `build_packet` 입력 형식으로 저장한다: `run_key, arm, patient_id, rep, criteria, final_questions`.
2. 원시 출력, `arrange` 결과, 제거 사유, `not_asked`를 조건과 함께 별도 저장한다. 평가자 패킷에는 넣지 않는다.
3. 사전 주석 잠금을 확인하기 전에는 유료 실행을 시작하지 않는다.
4. `stop_reason`, 재시도, 토큰, 시간, 한글 비율을 호출별로 기록한다.
5. 재판정의 `reassess` 직후와 `final_check` 직후 판정을 분리 저장한다.
6. 시뮬레이터 답변 개수·순서를 검사한다. `zip` 절단을 허용하지 않는다.
7. M8 입력은 잠금 전에 계산하지 않는다. 정답 대조는 `unblind` 통과 후에만 실행한다.
8. `scoring.py`에 집계 명령(환자×조건 평균·범위)과 이중 채점 비교 명령을 연결한다.
9. 시뮬레이터 감사 시트를 재판정 기록에서 생성한다.
