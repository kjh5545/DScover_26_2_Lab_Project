# 평가자 자격 지침 개정안 (팀 검토용)

**상태 (2026-11-05):** 결정 1은 **D1로 승인**(연구 담당자)되어 [04_annotation_guideline.md](04_annotation_guideline.md) 1절에 반영했다. 결정 2~5는 승인 전이다. 파일럿 채점 방식은 8절을 적용한다. 작성: 2026-11-04. 이 문서에는 조건 매핑, 환자 정보, 정답이 없다.

## 1. 바꾸려는 것

현행 지침은 연구 문서를 읽은 사람을 사전 주석자와 채점자에서 **일괄 제외**한다. 팀원 대부분이 연구 설계에 참여하는 소규모 팀에서는 평가자를 구하기 어렵다.

개정안은 노출을 **세 종류**로 나눈다. 셋은 위험의 크기와 경로가 달라서 같은 노출로 보지 않는다.

| 구분 | 내용 | 위험 경로 | 개정안의 취급 |
|---|---|---|---|
| **① 설계 지식** | 연구 목적, 연구 질문, 평가 정의(루브릭·M4a), 비교 조건의 종류와 차이, 분석 계획 | 기대하는 방향을 안다. 특정 질문 특징을 조건과 연결 지을 수 있다 | 선택지 D (1.1절) |
| **② 프롬프트 원문 친숙도** | 질문 생성 프롬프트를 작성·수정·열람했거나, 원문 규칙을 자세히 정리한 문서를 읽음 | 질문 문장의 표현·구조에서 조건을 알아볼 가능성이 ①보다 크다 | 선택지 P (1.1절) |
| **③ 항목 노출** | 채점하는 세트의 **조건 매핑**, 채점하는 환자의 **상세 정보와 기준별 정답** | 채점이 조건이나 정답에 직접 영향을 받는다 | **해당 항목의 채점 잠금 전에는 참여 불가** (선택지 없음) |

①과 ②는 본인 신고로 기록하고, 저장소 표기와 신고가 다르면 둘 다 적는다 (3절). ③은 실행기 잠금 순서와 관리자 보관으로 막는다.

### 1.1 선택지

**① 설계 지식**

| 안 | 내용 |
|---|---|
| D1 | 사전 주석·채점 모두 참여 가능. 이력 기록, 결과에 "설계 인지 평가자 포함" 표시 |
| D2 | 사전 주석만 참여 가능 (사전 주석은 생성 질문을 보지 않으므로 조건 추측 경로가 없다). 채점은 불가 |
| D3 | 현행 유지 (사전 주석·채점 모두 불가) |

**② 프롬프트 원문 친숙도**

| 안 | 내용 |
|---|---|
| P1 | 채점 불가, 사전 주석은 가능 (사전 주석은 질문을 보지 않는다) |
| P2 | 채점 가능. 단 눈가림 점검 필수, 친숙하지 않은 평가자와 짝, 결과를 평가자 유형별로도 보고 |
| P3 | 사전 주석·채점 모두 불가 (현행 "프롬프트 작성자가 아닐 것"을 열람자까지 확대) |

이 문서의 2절과 5절은 **D1·P1 조합**을 예시로 적용한다. 팀이 다른 조합을 고르면 2절 조건 3과 5절 판단을 그에 맞게 바꾼다.

## 2. 설계 인지 평가자의 조건

설계 지식이 있는 내부 평가자는 아래 조건을 **모두** 지키면 사전 주석자나 블라인드 채점자를 맡을 수 있다 (D1·P1 예시).

| 번호 | 조건 | 확인 방법 |
|---|---|---|
| 1 | 맡은 환자의 상세 정보와 기준별 정답을 **채점 잠금 전에 보지 않는다** | 본인 신고, 노출 기록 |
| 2 | 맡은 평가 세트의 **조건 매핑을 채점 잠금 전에 보지 않는다** (`sealed/`는 관리자만) | 실행기 잠금 순서, 관리자 기록 |
| 3 | (채점자만) 질문 생성 프롬프트 원문 친숙도가 없다. P2를 고르면 눈가림 점검·짝 구성으로 대신한다. 사전 주석자에게는 적용하지 않는다 (P1) | 본인 신고. 저장소 표기와 다르면 둘 다 기록 |
| 4 | **승인된 중립적 채점 지침만** 쓴다 (`04_annotation_guideline.md`, `04_error_taxonomy.md`). 연구 문서를 채점 근거로 쓰지 않는다 | 채점표 `rationale` 점검 |
| 5 | **다른 평가자와 독립으로** 채점하고, 조정 전 일치도(일치율과 κ)를 보고한다 | `compare-raters`, `annotation_tools.py compare` |
| 6 | 평가 정의 설계 참여와 노출 이력을 **사전에** 기록한다 | 아래 3절 |
| 7 | 채점 중 특정 세트의 조건을 짐작하게 되면 근거를 적지 말고 관리자에게 알린다 | 관리자 기록 |

**권장 (팀 결정):**
- **눈가림 점검:** 채점을 마친 뒤, 잠금 전에 각 세트의 조건을 추측해 적는다. 추측 정확도를 보고한다. 우연 수준을 크게 넘으면 그 평가자의 결과를 별도로 표시한다.
- **평가자 구성:** 가능하면 설계 인지 평가자와 비인지 평가자를 짝으로 둔다. 둘 다 있으면 평가자 유형별 결과도 함께 보고한다.

## 3. 노출 기록 항목

현행 `exposure_scope` 형식에 설계 노출 항목을 더한다. 양식 변경은 승인 후 반영한다.

```text
gold:<본 정답 범위>; factsheet:<본 상세 설명 범위>; prior_questions:<과거 생성 질문을 본 환자>;
prompts:<작성·열람한 질문 프롬프트>; design:<본 연구 문서와 절>; design_role:<평가 정의 설계 참여 내용>;
self_report_vs_records:<본인 신고와 저장소 기록이 다르면 둘 다 적음>; 시점:<주석 전|채점 전|채점 후>
```

- 본인 신고와 저장소 기록은 **따로** 적는다. 저장소의 역할 표기만으로 작성·열람을 추정하지 않는다. 반대로 신고만으로 기록을 지우지도 않는다.
- 결과 보고에 "설계 인지 평가자 포함"을 표시한다. "외부 독립 평가"로 표현하지 않는다.
- 정답 노출(`gold_exposed`)이 하나라도 있으면 현행대로 "독립적인 정답 블라인드 평가"로 표시하지 않는다.

## 4. 역할별 적용

| 역할 | 현행 | 개정안 |
|---|---|---|
| 사전 주석자 | 연구 문서 열람자 불가 | 2절 조건 충족 시 가능. 평가 정의 설계자가 주석하면 설계 비참여 주석자와 짝을 권장 |
| 블라인드 채점자 | 연구 문서 열람자 불가 | 2절 조건 충족 시 가능 |
| 조정자 | 해당 단계 평가자가 아닐 것 | 변경 없음 |
| 시뮬레이터 감사 | 채점 잠금 후 | 변경 없음. 상세 설명 노출을 기록 |
| 관리자 | 채점하지 않음 | 변경 없음 |

환자 단위로 적용한다. 같은 사람이 어떤 환자에서는 정답 노출자이고 다른 환자에서는 아닐 수 있다. 정답을 본 환자는 맡지 않는다.

| 4. 중립 지침 사용 | — | — | 배정 시 적용 |

| 6. 설계 참여 기록 | M4a 정의 검토·제안안 작성 | 제안안이 `04_question_rubric.md`, `M4a_team_review.md`(비공개 절 포함)를 기반 자료로 적음 | 기록하면 충족 |

**결론 (개정안, 팀 승인 전).** ③ 항목 노출은 확인 실험 네 환자에 대해 신고상 없다. ①은 있다 (M4a 정의 설계). ②는 신고상 없고 저장소 표기와 다르다.

| 선택 조합 | 확인 실험 네 환자 사전 주석 | 확인 실험 네 환자 채점 |
|---|---|---|
| D1 + P1 | 가능 | 가능 (신고 기준. 표기 차이는 병기) |
| D1 + P2 | 가능 | 가능. 눈가림 점검·짝 구성 필수 |
| D1 + P3 | 가능 | 가능 (신고 기준) |
| D2 + 어느 P | 가능 | 불가 |
| D3 | 불가 | 불가 |

- 팀이 저장소 표기를 신고보다 우선한다면 ②가 있는 것으로 보고 P 선택지를 그대로 적용한다 (P1이면 채점 불가, 사전 주석 가능).
- **파일럿 두 환자:** 정답 노출 있음(2026-11-05 신고). 8절을 적용한다.
- 사전 주석에 참여하면 평가 정의 설계자이므로 설계 비참여 주석자와 짝을 권장한다.

**현행 지침 기준으로는** 연구 문서 열람 때문에 사전 주석자·채점자가 불가하다. 승인 전까지는 이 판단이 유효하다.

## 7. 파일럿 단일 채점자 적용안 (2026-11-05)

**갱신:** D1 승인과 정답 노출 신고로 아래 표의 ①·③ 정답 행은 8절로 대체된다. 매핑 차단 운영 조건은 그대로 유효하다.

파일럿(S004·S008)에서 정서현 님이 생성 질문을 단독 채점하는 경우의 구체적 변경안이다. 사전 주석은 AI 주석이므로(`annotation_workflow.md` 6절) 사전 주석자 자격은 여기서 다루지 않는다.

**지침 변경안 (`04_annotation_guideline.md` 1절 평가자 행에 파일럿 예외 추가):**

> 파일럿 S004·S008에 한해 평가자 1명을 허용한다. 설계 지식(①)이 있는 평가자도 참여할 수 있다(D1). 조건 매핑, 맡은 환자의 정답·상세 설명, 프롬프트 파일은 계속 볼 수 없다. 결과에 "단일 평가자, 설계 인지 평가자"를 표시하고 일치도·κ를 보고하지 않는다. 채점을 마친 뒤 조건 공개 전에 세트별 조건 추측을 적는다(눈가림 점검).

**정서현 님에게 실제로 필요한 조건:**

| 구분 | 현재 상태 | 필요한 것 |
|---|---|---|
| ① 설계 지식 | 있음 (M4a 설계, 연구 문서 열람 기록) | 위 변경안 승인(D1). 현행 지침으로는 불가 |
| ② 프롬프트 친숙도 | 본인 신고: 작성·열람 안 함. 저장소 표기와 다름 | 6절 5번 결정(신고 우선 + 병기 등). 표기 우선이면 P1에서 채점 불가 |
| ③ 정답·상세 노출 (S004·S008) | **미신고** | 본인 신고. 본 적이 있으면 현행 규칙상 "독립적인 정답 블라인드 평가" 표시를 빼고, 이 개정안 4절 규칙상 그 환자는 맡지 않는다. 어느 규칙을 쓸지 정한다 |
| ③ 과거 생성 질문 노출 (S004·S008) | **미신고** | 본인 신고. 조건 표시와 함께 본 적이 있으면 항목 노출로 기록한다 |
| ③ 조건 매핑 | 매핑 생성 전 | 아래 운영 조건 |
| 단일 평가자 | — | 결과 표시 (실행기 `report`가 자동 표시) |

**운영 조건 (조건 매핑 차단):** 현행 지침은 "관리자는 채점하지 않는다"이다. 질문 생성과 채점표 생성을 정서현 님 계정에서 실행하면 관리자와 평가자가 겹친다. 가장 적은 추가 작업은 다음 둘 중 하나이다.
1. 다른 팀원 1명이 관리자를 맡아 `sealed/`(조건 매핑)를 보관한다. 생성 실행 기록 폴더는 채점 잠금 전까지 정서현 님이 열지 않는다.
2. 같은 계정에서 실행하되, 채점표 생성 직후 `sealed/`와 생성 기록 폴더를 다른 팀원에게 넘기고 로컬 사본을 지운다. 실행 중 화면에는 조건별 결과를 출력하지 않는다. 이 경우 "자기 관리 눈가림"으로 기록한다.

개정안 1절은 맡은 환자의 항목 노출(③)을 "선택지 없음"으로 두었다. 이 절은 **파일럿에 한해** 그 규칙의 예외를 정한다. 이 예외를 쓰는 대신 결과를 독립 평가로 보고하지 않는다.

### 8.1 검토: 노출이 채점에 줄 수 있는 영향

아래는 **가능한 경로**이다. 영향의 방향과 크기는 확인되지 않았다. 조건 매핑을 가려도 편향은 남을 수 있다.

| 채점 항목 | 가능한 영향 경로 |
|---|---|
| 조건 간 비교 | 정답·상세 정보를 알면 판단 기준이 달라질 수 있다. 그 변화가 모든 조건에 같게 작용한다는 보장은 없다. 조건마다 질문의 형태가 다르면 노출의 영향도 조건마다 다를 수 있다. 또 조건 표시가 있는 과거 질문을 본 적이 있어, 질문의 표현이나 구조에서 조건을 짐작할 수 있다 |
| 원문 보존·커버 판단 (M1, M3, M4a) | 환자의 실제 상태를 알면 "이 질문으로 확인된다"를 다르게 볼 수 있다. 영향의 크기는 미확인이다 |
| 전제 판단 (M2) | 실제 사실을 알면, 사실과 맞는 전제를 "미확인 전제"로 보지 못할 수 있다. 정답 노출로 인한 영향이 특히 우려되는 항목이다(크기는 미확인) |
| 정답 대조 지표 (M8 등) | 스크립트가 계산하므로 채점자 판단이 들어가지 않는다 |
| 사람 간 일치도 | 단일 평가자라 계산할 수 없다 |

결론: 절차와 지표의 작동을 점검하는 파일럿으로만 쓴다. 조건 간 차이는 탐색적으로만 서술하며, 효과의 방향·크기나 채점 신뢰도의 근거로 쓰지 않는다. 조건 짐작 가능성은 채점 후 눈가림 점검(각 세트의 조건 추측)으로 일부 측정할 수 있다. 시행 여부는 6절 결정 3이다.

### 8.2 지침 변경 (반영함)

`04_annotation_guideline.md` 1절에 다음을 반영했다.

1. **D1:** 설계 지식(연구 문서 열람, 평가 정의 설계 참여)은 평가자 제외 사유가 아니다. 노출 기록에 적고, 결과에 "설계 인지 평가자 포함"으로 표시한다. 프롬프트 파일과 조건 매핑은 계속 볼 수 없다.
2. **파일럿 탐색적 채점:** S004·S008에 한해 정답 노출 연구자가 단독 채점할 수 있다. 조건 매핑 차단은 예외가 없다.
3. **보고 표시 (필수):**
   - 결과 제목과 표에 "정답 노출 연구자의 탐색적 채점 (단일 평가자, 설계 인지)"으로 적는다.
   - "블라인드 평가", "독립 평가", "외부 평가"라는 표현을 쓰지 않는다. 조건 매핑을 가린 절차는 "조건 매핑 비공개 채점"으로 적고, 과거 조건 표시 질문 열람 때문에 조건 짐작 가능성이 있다고 함께 적는다.
   - 평가자 간 일치도와 κ를 보고하지 않는다.
   - 사전 주석은 "미검증 AI 주석"으로 함께 적는다.
   - M2(전제)는 정답 노출 영향이 특히 우려되는 항목으로 별도 표시한다. 영향의 크기는 미확인이라고 적는다.
   - 조건 매핑 차단 방식(8.4절의 A 또는 B)을 적는다.
4. **확인 실험:** 변경 없음. 네 환자의 사전 주석자·채점자는 해당 환자의 상세 정보·정답에 노출되지 않아야 한다(`gold_exposed: none`). 파일럿 예외는 확인 실험에 적용하지 않는다.

연구 담당자 지시(2026-11-05)에 따라 본인 신고(작성·열람 없음)를 기록하고, 저장소 표기는 별도로 보존한다. 표기만으로 친숙도를 확정하지 않는다. 노출 기록에는 `prompts:none(자기신고); repo_labels:4.1절 표기 있음(친숙도 판단에 쓰지 않음)`으로 둘 다 적는다.

### 8.4 조건 매핑 차단 방식

**매핑이 드러나는 경로 (코드 확인):**
- 실행 기록 `questions/`, `attempts/`, `answers/`, `downstream/`, `errors.jsonl`: 파일 이름과 내용에 조건 이름이 생성 질문과 함께 들어 있다.
- `sealed/blind_map.json`: 세트 번호와 조건의 대응표.
- **채점표 생성 시드:** 세트 번호와 순서는 시드와 실행 목록만으로 결정된다. 시드를 알면 위 파일을 열지 않아도 대응을 다시 계산할 수 있다. 기존 `packet --seed <정수>`는 시드를 명령줄과 화면에 남긴다. **2026-11-05에 시드를 생략하면 비밀 난수를 쓰고, 시드를 화면에 출력하지 않고 `sealed/`에만 저장하도록 바꿨다.**
- 화면 출력: 유료 실행 명령은 상태별 건수만 출력한다(예: `{"ok": 30}`). `plan` 명령은 실행 순서와 조건 이름을 출력하지만 세트 번호와 연결되지 않는다. 예기치 못한 오류의 상세 메시지에는 실행 키(조건 이름 포함)가 나올 수 있다.

| 방식 | 내용 | 차단 수준 | 보고 표시 |
|---|---|---|---|
| **A. 별도 관리자 (현행 규칙)** | 채점하지 않는 다른 사람이 질문 생성·후속 실행·채점표 생성을 맡는다. 실행 기록과 `sealed/`를 보관하고, 채점자에게는 `rater_packet/`만 넘긴다. 실행을 채점자 계정에서 했다면 채점표 생성 직후 실행 기록과 `sealed/`를 관리자에게 넘기고 채점자 쪽 사본을 지운다 | 접근 자체를 막는다 | "조건 매핑 비공개 채점 (별도 관리자 보관)" |
| **B. 자동 봉인·로그 가림 (대안)** | 같은 계정에서 실행한다. ① 화면에는 건수만 출력하고 상세 오류는 파일에만 남긴다. ② 시드는 비밀 난수로 만들고 출력하지 않는다(반영함). ③ 채점표 생성 직후 실행 기록과 `sealed/`를 하나의 봉인 묶음으로 옮기고 해시를 기록한다. ④ 채점 잠금 후에만 봉인을 푼다. ⑤ Claude 등 실행을 돕는 도구도 봉인 묶음을 읽거나 출력하지 않는다 | **실수로 보는 것은 막지만, 본인이 여는 것은 막지 못한다.** 해시는 변경을 드러낼 뿐, 열람 여부는 증명하지 않는다 | "조건 매핑 비공개 채점 (자기 관리 봉인, 열람 차단 장치 없음)" |

**결정 (연구 담당자, 2026-11-05): B를 선택한다.** 구현 내용은 다음과 같고, mock 테스트로 검증했다.
- `packet` 명령은 비밀 시드로 채점표를 만든 직후 **자동으로 봉인**한다. 실행 기록과 `sealed/`를 `sealed_bundle.zip` 하나로 옮기고 원본을 지운다. 해시와 한계 문구는 `seal_record.json`에 남는다. 화면에는 건수만 출력한다.
- 봉인된 실험 폴더에서는 질문 생성과 후속 실행을 다시 할 수 없다.
- `unseal`은 `lock-scores`가 끝나고 채점 확정표가 잠금 후 바뀌지 않았을 때만 묶음을 푼다. 묶음의 해시가 바뀌었으면 거부한다.
- `merge`와 `lock-scores`는 채점표의 `rater_id`가 잠금 기록에 등록된 채점자 ID(SH01)인지 검사한다.
- `report`는 봉인 한계 문구를 출력한다.

**한계 (보존):** 자기 관리 봉인이다. 같은 계정에서 묶음을 열 수 있으며 실제 접근 차단 장치가 없다. 해시는 봉인 후 변경만 드러내고 열람 여부를 증명하지 않는다.

**운영 규칙:**
- 채점 잠금 전까지 채점자와 Claude는 실험 폴더에서 `rater_packet/` 외의 파일을 열거나 출력하지 않는다.
- smoke 폴더(`smoke…/`)에도 같은 프롬프트로 생성한 조건 표시 질문이 남으므로 열지 않는다.
