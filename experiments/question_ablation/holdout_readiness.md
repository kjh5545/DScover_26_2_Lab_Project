### 2.5 질문 생성 입력 형식의 일관성 [확인]

handoff와 평가 세트 묶음은 형식이 두 군데 다르고, 둘 다 질문 생성 입력에 영향을 준다 (`src/question_builder.py` 294~314행).

| 차이 | 평가 세트 묶음 (S) | handoff (N) | 입력 영향 |
|---|---|---|---|
| 기준의 `needed_info` | 없음 | 있음 | 기준마다 "(필요한 정보: …)"가 붙는다 |
| 시험 제목 | NCT 번호 | 실제 제목 | 시험 머리글에 " · 제목"이 붙는다 |

`holdout.load_bundle`의 기본값(`goldset`, 파일럿 형식)은 두 차이를 모두 없앤다. 기준은 (id, type, text)만 남기고, 제목은 NCT 번호로 두고, 시험별 최종 판단은 파일럿과 같은 함수(`matcher.final_judgment`)로 다시 계산한다. 이 형식에서 여섯 환자(파일럿 2, 확인 4)의 입력 형식 요소(머리글 구성, 제목·필요 정보 유무, 기준 필드)가 같고, 다시 계산한 최종 판단도 원래 값과 같다. `service` 형식을 고르면 N 환자만 두 요소가 들어간다. 어느 형식을 쓸지는 팀 결정이다.

### 2.6 초기 판정의 출처·버전·입력 범위 [확인]

| 환자 | 출처 | 생성 시점 | 모델·판정 프롬프트 | 판정기 입력 |
|---|---|---|---|---|
| S004, S008, S002, S010 | 평가 세트 v3 판정 캐시 (`scripts/eval_vs_goldset.py`) | 2026-10-15 (`b770e0b`), 프로필 2026-10-12 (`d23a94c`) | `claude-sonnet-5-5`, v3 | 짧은 원래 설명 + 그 설명에서 만든 프로필 |
| N001, N002 | handoff (`src.pipeline.run_intake`, 1~4단계) | 2026-10-22 (`a49ddc1`) | `claude-sonnet-5-5`, v3 | 같음 |

- **상세 설명·정답 미사용:** 판정기 프롬프트는 "환자의 원래 설명과 그 설명에서 만든 프로필"만 받는다 (`src/agents/matcher.py` 18~34행). 여섯 환자 모두 입력된 설명이 시트의 짧은 설명과 같다. 상세 설명에만 있는 문장 조각과, 짧은 설명에 없는 정답 근거 문장이 프로필·초기 판정·질문 생성 입력(두 형식 모두)에 나타난 건수는 **모두 0**이다. 내용은 출력하지 않았다.
- **시점:** 초기 판정은 네 환자의 정답이 채워진 2026-11-04보다 앞선다.
- **코드 규칙 차이:** handoff 판정에는 나이·임신 코드 규칙이 적용되어 있고(환자당 2개 기준), 평가 세트 캐시는 LLM 판정만 저장하고 코드 규칙은 채점 때 적용한다. 여섯 환자 모두에 코드 규칙을 적용해 보면 **판정이 바뀌는 기준은 0개**이다. 따라서 질문 후보와 입력은 어느 방식이든 같다.
- 출력 검사(validator)로 고쳐진 판정은 여섯 환자 모두 0개이다.

**현재 지침과의 대조:** `04_annotation_guideline.md` 1절은 평가자 조건을 "질문 프롬프트 작성자가 아닐 것"으로 두고, 평가자가 볼 수 없는 것에 "조건 매핑, 정답, 상세 환자 설명, 프롬프트 파일, 연구 문서"를 둔다. 사전 주석자도 연구 문서를 볼 수 없다.

**판단:**

1. **프롬프트 작성 여부는 평가자 제외 근거로 확정하지 않는다.** 이전에 "프롬프트 작성자이므로 제외"라고 안내한 것은 역할 문서에 근거한 가정이었다. 이를 철회한다. 기록이 충돌하므로 팀 확인 전까지 "미확정"으로 둔다.
2. **그러나 현재 지침으로는 블라인드 평가자(채점자)와 사전 주석자를 맡을 수 없다.** 근거는 프롬프트 작성 여부가 아니라 연구 문서 열람이다. 이 열람은 본인 제안안에 기록되어 있으며 작성 여부와 무관하게 성립한다. `05_5_preflight_review.md` 4.2절도 "M4a 비공개 절 검토자 + 주석자"는 피하도록 했다.
3. 현재 지침으로 맡을 수 있는 역할은 다음과 같다.
   - **불일치 조정자:** 해당 단계의 평가자가 아니면 된다. 조건 매핑만 보지 않으면 된다.
   - **시뮬레이터 감사 평가자:** 채점 잠금 후 단계이다. 단, 상세 설명을 보게 되므로 그 시점부터 해당 환자의 Fact Sheet 노출자로 기록한다.
   - **관리자:** 다만 이 경우 채점에는 참여하지 않는다.
4. **개정안 기준 (팀 검토용, [04_rater_policy_revision_proposal.md](04_rater_policy_revision_proposal.md) 5절):** 개정안은 설계 지식(①), 프롬프트 원문 친숙도(②), 항목 노출(③)을 나눈다. 서현 님은 확인 실험 네 환자에 대해 ③이 없고(신고), ①이 있으며, ②는 신고상 없고 저장소 표기와 다르다. 팀이 고르는 조합에 따라 사전 주석은 D1·D2에서 가능, 채점은 D1에서 가능하다(P2면 눈가림 점검·짝 구성 필수). 파일럿 두 환자는 정답·상세 노출 신고 후 판단한다. **개정안이 승인되기 전까지는 3번의 현행 판단이 유효하다.**
5. **2026-11-05 갱신:** D1이 승인되어 설계 지식은 더 이상 제외 사유가 아니다(3번 판단은 설계 지식 부분에 한해 대체된다). S004·S008은 정답 노출 `full`이므로, 파일럿 채점은 개정안 8절의 **정답 노출 연구자의 탐색적 채점**으로만 할 수 있다. 확인 실험 네 환자의 비노출 요건은 그대로이다.

**노출 기록 초안** (`rater_registry` 형식. 가명 ID는 관리자가 배정하고 실명 대응표는 저장소 밖에 보관):

| 항목 | 값 |
|---|---|
| rater_id | (배정 전) |
| role | 파일럿: rater (정답 노출 연구자의 탐색적 채점). 확인 실험: 배정 전 |
| gold_exposed | S004·S008: `full` (goldset 작성자, 자기신고 2026-11-05). S002·S010·N001·N002: `none` (자기신고 2026-11-04) |
| exposure_scope | `gold:full(S004·S008, goldset 작성자), none(확인 후보 4명); factsheet:봤음(S004·S008, 2026-11-05 신고), none(확인 후보 4명); prior_questions:조건 표시와 함께 봤음(S004·S008, 2026-11-05 신고); prompts:none(자기신고 유지); repo_labels:4.1절 표기 있음(별도 보존, 친숙도 판단에 쓰지 않음); research_docs:M4a_team_review(v1, 비공개 5절 포함), 04_annotation_guideline, 04_question_rubric; design:D1 승인(2026-11-05); 시점:채점 전` |

`gold_exposed`는 한 칸이라 환자별 값을 담지 못한다. 파일럿 기록에는 `full`, 확인 실험 기록에는 `none`으로 따로 적는다.
