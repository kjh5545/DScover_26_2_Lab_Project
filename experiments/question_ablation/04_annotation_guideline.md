## 1. 역할과 접근 범위

| 역할 | 조건 | 담당 | 볼 수 있는 것 | 볼 수 없는 것 |
|---|---|---|---|---|
| 사전 주석자 2명 | 질문 프롬프트 작성자가 아닐 것 | ( ) ( ) | 주석표, 이 지침 | 정답(이번 작업 중), 상세 환자 설명, 생성 질문, 연구 문서 |
| 평가자 2명 | 질문 프롬프트 작성자가 아닐 것 | ( ) ( ) | 채점표, 이 지침, 오류 분류표 | 조건 매핑, 정답, 상세 환자 설명, 프롬프트 파일, 연구 문서 |
| 조정자 1명 | 평가자가 아닐 것 | ( ) | 불일치 목록 | 조건 매핑 |
| 관리자 1명 | 채점하지 않을 것 | ( ) | 조건 매핑(`sealed/`) | 잠금 전 내용 전달 금지 |

연구 문서는 `01`~`03`, `04_question_rubric.md`, `prompts/` 폴더를 말한다. 평가 대상과 가설이 들어 있으므로 잠금 전에는 열지 않는다. 팀 대화에서도 특정 질문의 출처나 기대 결과를 묻지 않는다.

한 사람이 사전 주석자와 평가자를 겸할 수 있다. 가능하면 두 명이 독립적으로 평가한다.

**파일럿 예외 (2026-11-05, 연구 담당자 승인 운영 방식):** S004·S008 파일럿은 사전 주석자 2명 대신 미검증 AI 주석 1부를 쓴다. 절차와 표시는 `annotation_workflow.md` 6절을 따른다. 확인 실험에는 적용하지 않는다.

**설계 지식 (D1, 2026-11-05 승인):** 연구 문서를 이미 읽었거나 평가 정의 설계에 참여한 사람도 사전 주석자·평가자를 맡을 수 있다. 위 표의 "연구 문서" 금지는 아직 읽지 않은 사람에게 계속 적용한다. 설계 지식이 있는 사람은 노출 기록에 적고, 결과에 "설계 인지 평가자 포함"으로 표시한다. 채점 근거는 이 지침과 `04_error_taxonomy.md`만 쓴다. 프롬프트 파일과 조건 매핑 금지는 바뀌지 않는다.

**파일럿 탐색적 채점 (2026-11-05):** S004·S008에 한해, 그 환자의 정답에 노출된 연구자가 단독으로 채점할 수 있다. 이 경우 결과를 **"정답 노출 연구자의 탐색적 채점 (단일 평가자, 설계 인지)"**으로 표시한다. "블라인드 평가", "독립 평가", "외부 평가"라고 쓰지 않으며, 평가자 간 일치도·κ를 보고하지 않는다. 조건 매핑을 가려도 노출로 인한 편향은 남을 수 있으며 그 방향·크기는 미확인이라고 적는다. 전제 판단(M2)은 정답 노출 영향이 특히 우려되는 항목으로 따로 표시한다. 조건 매핑은 예외 없이 채점 잠금 전까지 볼 수 없으며, 차단 방식(별도 관리자 또는 자기 관리 봉인)을 결과에 적는다. 근거와 검토는 `04_rater_policy_revision_proposal.md` 8절에 있다.

**확인 실험 (S002·S010·N001·N002):** 위 파일럿 예외를 적용하지 않는다. 사전 주석자와 평가자는 맡은 환자의 상세 정보·정답에 노출되지 않아야 한다(`gold_exposed: none`).

**정답 노출 기록:** 정답 시트나 평가 세트를 본 적이 있는 사람도 참여할 수 있다. 다만 `rater_registry_template.csv`에 노출 여부(`none`, `partial`, `full`)와 범위를 기록한다. 노출자가 한 명이라도 있으면 결과를 **독립적인 정답 블라인드 평가로 표시하지 않는다.** 조건 가림은 그대로 유지한다.

## 3. 사전 주석

파일: `evaluation/preannotation/S004_preannotation.csv`, `S008_preannotation.csv`

`is_candidate=1`인 행만 작성한다. 다른 행은 맥락 참고용이다. `initial_verdict`는 초기 판정이며 정답이 아니다.

### 3.1 항목

**askable: 이 정보를 지금 확보할 수 있는가**

| 값 | 기준 |
|---|---|
| ASK_PATIENT | 환자가 직접 답할 수 있다. |
| ASK_RECORD | 기존 기록이나 결과지로 확인할 수 있다. |
| NOT_OBTAINABLE | 환자에게도 기존 기록에도 없고, 등록 후 시험팀만 확인할 수 있다. |
| UNSURE | 판단 불가 (사유 필수) |

**centrality: 시험 대상 핵심성** (H를 정하는 항목)

| 값 | 기준 |
|---|---|
| 2 | 연구 대상 집단을 정의하는 핵심 조건, 또는 해당 시험 중재에 직접 관련된 핵심 안전 조건이다. 대상 질환·병기·필수 치료력, 그리고 근거가 있는 중재 관련 안전 제외 조건을 포함한다. |
| 1 | 대상·중재에 특화된 핵심 조건은 아니지만 일반 건강·안전 상태에 관한 요건이다. |
| 0 | 참여 운영·행정·절차에 관한 요건이다. |
| UNSURE | 아래 근거만으로 2·1·0점을 구분하기 어렵다. 이유를 적고 조정한다. |

**판단 원칙**

- 동반 질환·병용 약물·검사라는 항목 이름만으로 1점이나 2점을 주지 않는다. 해당 시험에서 그 조건이 하는 역할을 본다.
- "필수 치료력"은 대상 집단을 정하는 필수 선행 치료, 치료 실패, 치료 경험 요건을 뜻한다. 모든 치료력을 자동으로 2점으로 보지 않는다.
- 선정·제외 기준에 일괄 우선순위를 두지 않는다. 안전 조건은 선정 기준에 적힐 수도 있다.
- 한 조건이 대상 정의와 안전 역할을 함께 해도 2점을 넘겨 가산하지 않는다.
- 확인할 정보가 많거나 여러 질문·기록이 필요하다는 이유로 낮추지 않는다.
- 실제 환자의 탈락 가능성, 정답, 생성 결과를 추측해 점수를 정하지 않는다.

**안전 조건의 근거** (`centrality_evidence`)

- 안전 조건의 2점은 **근거가 있을 때만** 준다. 근거는 두 가지이다.
  1. 기준 원문이나 시험 문서의 **명시적 설명**. `원문: <해당 문구>`로 적는다.
  2. 주석 전에 고정한 **공통 근거 목록** `evaluation/preannotation/safety_evidence.csv`의 항목 중 `review_status`가 "고정"인 것. 근거 ID(`EV01` 등)를 적는다. 검토 대기 항목은 인용할 수 없다.
- **약물명이나 계열이 원문에 나온다는 것만으로는 2점이 아니다.** 그 조건이 시험 중재의 안전과 직접 관련된다는 설명이 원문이나 근거 목록에 있어야 한다.
- 일반 건강·안전 요건으로 분류할 근거가 충분하면 1점이다.
- **근거가 부족해 2점과 1점을 구분하기 어려우면 1점으로 낮추지 말고 UNSURE**로 적고 사유를 남긴다. 조정에서 정한다.
- 일반 의학 지식이나 약리 지식만으로 추측하지 않는다. 근거 목록에 없는 자료를 각자 찾아보지 않는다.
- 핵심성 2점에는 `centrality_evidence`가 반드시 있어야 한다. 대상 정의 조건이면 `원문: <대상 정의 문구>`로 적는다.

**핵심 부분** (`core_part`, `core_info`: **핵심성 2점 기준은 모두 필수**)

- 핵심 부분의 범위는 **사전 주석 단계에서** 정하고 잠근다. 생성 질문을 보기 전이다. 채점 단계에서는 바꾸지 않는다.
- 원기준에 여러 하위 조건이 섞여 있고 그중 일부만 핵심이면, 핵심으로 본 하위 조건의 원문 표현을 `core_part`에 적는다.
- **원기준 전체가 핵심이면 `core_part`에 `전체`라고 적는다.** 빈칸은 표시 누락으로 보고 검사에서 걸린다.
- 어느 경우든 그 핵심 부분을 판정하는 데 필요한 정보를 `core_info`에 적는다. 핵심으로 본 이유와 비핵심 부분의 구분은 `rationale`에 적는다.
- 관련 단어나 질환이 언급됐다는 것만으로 핵심 부분을 지정하지 않는다. 하위 조건 구분이 불명확하면 `needs_review`에 Y를 적어 조정한다.
- 가상 예시: "특정 질환으로 확진되었고 정기 방문이 가능해야 한다" → 핵심 부분 "특정 질환으로 확진", 필요한 정보 "확진 여부와 근거(병리 결과 등)". "조직검사로 확인된 특정 질환" → 핵심 부분 "전체", 필요한 정보 "조직검사 결과".

판정 직접성(`decisiveness`)은 2026-11-04부터 주석하지 않는다 (M4a v2 확정, M7-B).

### 3.2 핵심 기준(H)

H는 평가자가 정하지 않고 계산한다. **조정 후 핵심성이 2점인 기준이 H이다.** 확인하기 쉬운지는 H에 반영하지 않는다.

### 3.3 판단 원칙

- 기준 자체의 성격만 평가한다.
- **이 환자가 해당될 가능성을 추측하지 않는다.** 질병의 일반적 경향으로 탈락 가능성을 짐작하지 않는다.
- 선정 기준과 제외 기준에 일괄 가중치를 두지 않는다.
- 여러 시험에 공통이라는 이유로 점수를 올리지 않는다. 공통성은 군집표에 따로 적는다.
- 질문 5개 예산을 고려해 H 수를 맞추지 않는다.

### 3.4 동률과 등급 분포

- **기준 간 순위를 매기지 않는다.** 같은 등급은 동률로 둔다.
- H가 예산으로 다룰 수 있는 수보다 많아도 그대로 둔다. H 수는 결과와 함께 보고한다.
- 환자별 H가 0개여도 H를 만들거나 기준을 바꾸지 않는다. 그 환자의 M4a는 값 없음으로 보고된다. 관리자에게 알려 기록한다.

### 3.5 공유정보 군집

파일: `shared_cluster_template.csv`

서로 다른 기준이 **같은 사실**을 필요로 하면 같은 `cluster_id`로 묶고 `shared_fact`에 그 사실을 적는다. 기간·대상·측정값이 다르면 묶지 않는다. 같은 질환에 관한 기준이라는 것만으로는 군집이 아니다. 군집이 없으면 빈 표로 둔다.

### 3.6 조정

1. 두 주석자의 항목별 일치도를 계산한다 (`annotation_tools.py compare`).
2. 불일치 항목을 `adjudication_template.csv`에 옮긴다 (같은 명령이 만든다).
3. 두 주석자가 토의하고, 합의되지 않으면 조정자가 결정한다. 결정과 이유를 기록한다.
4. 확정 결과를 `preannotation_final_template.csv` 형식으로 저장한다 (`annotation_tools.py finalize`).

| 열 | 값 |
|---|---|
| final_centrality | 조정 후 핵심성 |
| final_centrality_evidence | 조정 후 근거. 핵심성 2점이면 필수 |
| final_core_part, final_core_info | 조정 후 핵심 부분(또는 `전체`)과 필요한 정보. 핵심성 2점 기준에는 필수, 다른 기준에는 비운다 |
| h_strict | final_centrality가 2이면 true (주 분석) |
| h_any | 조정 전 한 주석자라도 핵심성 2이면 true |

핵심성 UNSURE가 조정 후에도 남으면 H로 보지 않고 건수를 기록한다. 주석자가 1명뿐이면 `h_strict`와 `h_any`가 같아지며, 이를 한계로 보고한다.

근거·핵심 부분 문구는 한 주석자라도 핵심성 2점을 주었고 두 문구가 다르면 조정 대상이 된다.

확정표는 `preannotation/S004_final.csv`, `S008_final.csv`, 군집표는 `S004_clusters.csv`, `S008_clusters.csv`로 저장한다. 공통 근거 목록 `safety_evidence.csv`도 함께 잠근다. 목록을 쓰지 않으면 머리글만 있는 파일을 잠근다. 관리자가 `annotation_record_template.json`을 채워 잠금 명령을 실행한다. 핵심 기준(M4a) 정의 검토 결과, 담당자, 정답 노출 범위가 함께 기록된다. 잠금 후 파일이 바뀌면 실행이 차단된다. 잠금 후 변경은 금지한다. 오류를 발견하면 원본을 두고 변경 사유와 영향 범위를 기록한다.

## 4. 블라인드 채점

### 4.1 채점표

- `question_sheet.csv`: 질문 1개당 1행
- `link_sheet.csv`: 질문과 기준의 연결 1건당 1행
- JSON 파일은 같은 내용이며 도구 연동에 쓴다.

`blind_id`는 한 세트를 뜻한다. `question_no`는 세트 안의 순서이다. 세트의 순서에는 의미가 없다. **세트 단위로 묶어서 읽되, 같은 환자의 다른 세트와 비교하지 않는다.** 어떤 세트가 어떤 방식으로 만들어졌는지 추측하지 않는다. 추측이 들면 `rationale`이 아니라 관리자에게 알린다.

환자의 기준 정보는 사전 주석 파일의 `patient_text`를 쓴다. 다른 자료는 쓰지 않는다.

### 4.2 판단 순서

연결 1건마다 다음 순서로 본다.

1. **coverage:** 답을 받으면 이 기준 판정에 필요한 정보가 나오는가?
   - 전부 나옴: FULL
   - 일부만: PARTIAL + C2, C3, G5 중 하나. C3는 기록이 있는지만 물은 경우이다.
   - 전혀 아님: NONE + C1
   - **core_coverage:** `core_part` 칸이 채워진 연결(핵심 기준)마다 판단한다. 비어 있으면 NA이다. `core_part`와 `core_info`는 사전 주석에서 정해진 값이므로 고치지 않는다. `core_part`가 `전체`이면 원기준 전체가 핵심 부분이다. 핵심 부분에 필요한 정보(`core_info`)를 모두 요청하면 FULL, 일부를 실제로 요청하면 PARTIAL, 요청하지 않으면 NONE이다(비핵심 부분만 물은 경우 포함). 원기준 coverage가 FULL이면 FULL, NONE이면 NONE이다. `전체`일 때 FULL은 원기준 coverage도 FULL이어야 한다. 관련 단어만 언급하거나 기록 보유 여부만 물은 것은 PARTIAL의 근거가 아니다. 답을 받았을 때 핵심 부분 판정에 쓸 수 있는 어떤 정보가 나오는지 설명할 수 있어야 한다. 판단할 수 없으면 UNSURE와 사유를 적는다.
   - `core_part`가 채워진 기준은 핵심 기준이다. 평가자는 이 칸으로 어떤 기준이 핵심 기준인지 알게 된다. 이 사실은 노출 기록에 남긴다.
2. **preservation:** NONE이면 NA이다. 아니면, 질문이 다룬 조건의 의미가 원문과 같은가?
   - 같음: PASS
   - 바뀜: FAIL + F 코드
3. **group_validity:** 기준이 1개만 연결된 질문이면 NA이다. 아니면, 답변이 이 기준에 필요한 같은 사실을 제공하는가?
   - 예: VALID
   - 아니오 또는 NONE: INVALID

질문 1개마다 다음을 본다.

| 항목 | 질문 |
|---|---|
| assumption | 환자 설명에 없는 사실을 일어난 것으로 전제하는가? 있으면 FAIL + A 코드. |
| redundancy | 같은 세트의 앞 질문이나 환자 설명에 있는 정보를 다시 묻는가? 있으면 FAIL + R 코드. |
| single_topic | 독립된 사실을 한 번호에 넣었는가? 있으면 FAIL + T1. |
| overgroup | 다기준 질문이 서로 다른 사실을 합쳤는가? 있으면 FAIL + G 코드. 기준 1개 질문은 NA. |

### 4.3 자주 헷갈리는 판단

| 상황 | 판단 |
|---|---|
| 질문에 조건이 언급되지 않음 | 왜곡이 아니다. PARTIAL이다. |
| 질문이 조건을 다른 값으로 바꿈 | 왜곡이다. `needed_info`가 정확해도 FAIL이다. |
| 질문이 조건을 넓혀 묻고 나중에 대조할 수 있음 | 원문 기준이 왜곡되지 않고 필요한 사실이 모두 나오면 PASS이다. 예: "등록 전 3개월" 기준에 실제 날짜를 묻는 경우. |
| "최근" 같은 표현으로 기준 날짜를 대체 | F1이다. |
| `resolves`에 있으나 답으로 알 수 없음 | NONE + C1이다. 연결되어 있다는 사실은 근거가 아니다. |
| 내용 제공을 요청하는 기록 질문 | 필요한 항목이 지정되면 FULL일 수 있다. 수치를 묻지 않았다는 이유로 낮추지 않는다. |
| 보유 여부만 묻는 기록 질문 | PARTIAL + C3이다. |
| 영어 원문과 한국어 질문 | 의학적으로 같은 뜻이면 PASS이다. 쉬운 말로 풀어도 범위가 같으면 PASS이다. |
| 정보가 충분하지 않음 | 추측하지 말고 UNSURE와 사유를 적는다. |
| "받으셨다면 ~" | 조건문은 가정이 아니다. |

### 4.4 기록

FAIL, PARTIAL, NONE, INVALID에는 `rationale`을 한 문장 이상 적는다. 문제가 되는 원문 표현과 질문 표현을 인용한다. UNSURE에는 `unsure_reason`을 적는다. 재검토가 필요하면 `needs_review`에 Y를 적는다.

작성 후 다음 명령으로 형식을 검사한다.

```bash
python scoring.py validate question_sheet.csv link_sheet.csv
```

## 5. 이중 채점과 불일치 조정

| 항목 | 규칙 |
|---|---|
| 대상 | 관리자가 환자×세트 구분별 1세트 이상, 전체의 약 1/3을 고른다. 평가자에게는 blind_id만 전달한다. |
| 순서 | 두 평가자가 독립 채점한다. 상대의 결과를 보지 않는다. |
| 일치도 | 항목별 일치율과 Cohen's κ를 함께 보고한다. FAIL이 드물면 κ가 낮게 나올 수 있으므로 일치율도 본다. |
| 재교육 기준 | 주요 항목에서 κ < 0.6이거나 일치율 < 0.8이면 해석 차이를 정리한 뒤 나머지 세트를 채점한다. |
| 조정 | 불일치를 `adjudication_template.csv`에 기록한다. 두 평가자가 토의하고 합의되지 않으면 조정자가 결정한다. 이유를 남긴다. |
| 원본 보존 | 각 평가자의 원본 채점표를 수정하지 않는다. |
| 지침 변경 | 실제 질문을 본 뒤 판단 기준을 바꾸면 변경 내용을 기록하고 이미 채점한 세트에 다시 적용한다. |

## 6. 잠금과 공개

1. 모든 불일치를 조정하고 형식 검사를 통과한다.
2. 관리자가 확정 채점표를 잠근다.

```bash
python scoring.py lock <봉인 폴더> question_final.csv link_final.csv
```

3. 잠금 후에만 조건 매핑을 공개한다. `unblind`는 잠금 기록이 없거나 파일이 바뀌면 거부한다.
4. 공개 후 채점을 수정해야 하면 원본을 두고 수정 사유, 영향 항목, 수정 후 값을 별도로 보고한다.

## 7. 시뮬레이터 응답 감사

재판정을 수행한 세트에 대해 채점 잠금 후 수행한다. `simulator_audit_template.csv`에 질문, 답변, 사실 자료를 넣고 `S0`~`S4`를 기록한다. 이 단계에서만 평가자가 상세 설명을 본다. 따라서 **채점 잠금 전에는 시작하지 않는다.**
