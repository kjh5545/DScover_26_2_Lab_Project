# STEP 6 단계별 실행 계획

**계획 문서이며 승인이 아니다.** 각 Phase는 시작 전에 따로 승인받는다. 금액은 추정이다. 가격은 공식 문서의 입력 $2, 출력 $10 (100만 토큰당) 기준이다. 명령은 [05_5_preflight_review.md](05_5_preflight_review.md) 7절에 있다.

| Phase | 내용 | 호출 | 예상 비용 | 현재 |
|---|---|---|---|---|
| 6A | 소규모 연동 테스트 | 7~8 | 약 $0.12~0.30 | `smoke` 구현됨. 6A-0은 키·승인 대기, 6A-1·2는 주석 잠금 후 |
| 6B | 질문 생성 | 30 | $1.20~2.70 | 차단 |
| 6C | 블라인드 채점 | 0 | 없음 | 6B 이후 |
| 6D | 후속 판정 | 96~120 | $1.03~2.88 | 차단 |

재시도 10% 가정을 포함한 6B + 6D 합계는 약 $2.5~6.1이다. 6A는 이 추정 밖이다.

## Phase 6A: 소규모 실제 API 연동 테스트

**구현 상태:** `run_pilot.py smoke <단계>`로 구현하였다 (2026-11-03, 테스트 8건). 실험 ID는 `smoke`로 시작해야 하고, 파일럿 명령은 이 ID를 거부한다. 실행 계획이 파일럿과 달라 같은 폴더에 섞이지 않는다. **`questions`를 다른 실험 ID로 실행하면 30회가 모두 호출되므로 연동 테스트로 쓰면 안 된다.** 명령과 자동 중단 조건은 [05_5_preflight_review.md](05_5_preflight_review.md) 7.5절에 있다.

| 단계 | 명령 | 내용 | 호출 | 예상 비용 |
|---|---|---|---|---|
| 6A-0 | `smoke ping` | 모델 조회, 짧은 고정 문구 호출 (실험 데이터 없음) | 조회 1 + 메시지 1 | $0.001 미만 |
| 6A-1 | `smoke questions` | S004: C0, C_full 질문 생성 | 2 | $0.08~0.18 |
| 6A-2 | `smoke downstream` | C_full 1세트의 시뮬레이터 → `reassess` → `final_check` | 4~5 | $0.04~0.12 |

**최대 비용:** 메시지 호출 1회는 출력 상한 16,000토큰($0.16)과 입력 2만 토큰 이하 가정($0.04)에서 약 $0.20이다. 7회 약 $1.40, 형식 재시도까지 모두 발생하면 약 $2.80이다. 측정값이 아니라 안전 상한이다.

| 항목 | 내용 |
|---|---|
| 진입 조건 | 6A-0: API 키, 사용자 승인. 6A-1·2: 사전 주석 잠금, 사용자 승인 (코드가 잠금을 검사한다) |
| 확인 사항 | 인증 성공, 응답 `model`이 `claude-sonnet-5-5`와 일치, JSON 파싱, 한국어 질문, C0 출력 형식, `stop_reason`, 호출별 토큰, `cost_usd`가 0이 아닌지 |
| 저장 위치 | `data/processed/question_ablation/smoke1/` |
| 데이터 사용 | **분석에서 제외한다.** 관리자만 본다. 주석자와 평가자에게 보여 주지 않는다. |
| 중단 조건 | 401·403·404, 응답 모델 불일치, 3회 연속 API 오류, 호출당 비용 $0.20 초과, 누계 $1.00 도달, 구조적 파싱 실패. 형식 실패 외에는 코드가 자동으로 멈춘다 |
| 금지 | 결과를 보고 프롬프트나 실행 조건을 바꾸지 않는다. 문제가 있으면 기록하고 보고한다. |

## Phase 6B: 질문 생성 파일럿

5조건 × 2환자 × 3회 = 30회. 순서는 `run_manifest.json`에 고정되어 있다.

| 항목 | 내용 |
|---|---|
| 진입 조건 | 6A 통과, `check`에서 annotation·versions 통과, 실험 폴더 밖 변경 없음, 사용자 승인 |
| 예상 호출 | 30 + 형식 재시도 |
| 예상 비용 | $1.20~2.70 (재시도 별도) |
| 결과 저장 | `data/processed/question_ablation/pilot1/`: `questions/`, `attempts/`, `errors.jsonl`, `experiment.json`, `run_manifest.json` |
| 확인 | 완료 건수, `failed_format`, `refused`, 조건별 D9 표시, 실제 비용 정산 |
| 자동 중단 | API 오류 3회 연속, 고정 값 변경 |
| 수동 중단 | 실제 비용이 $4.05(상한의 1.5배)를 넘으면 후속 단계 전 재승인. **실행기에 비용 차단 기능은 없다.** |
| 금지 | 실패 건을 결과가 나쁘다는 이유로 다시 뽑지 않는다. 이미 저장된 실행은 재호출되지 않는다. |

## Phase 6C: 블라인드 질문 채점

| 순서 | 작업 | 담당 |
|---|---|---|
| 1 | `packet`으로 채점표 생성. 시드는 비공개, **한 번만 실행** | 관리자 |
| 2 | `rater_packet/`만 전달. `sealed/double_score_sets.json`의 세트를 이중 채점으로 지정 | 관리자 |
| 3 | 독립 채점, `validate` 형식 검사 | 평가자 |
| 4 | `compare-raters`로 일치도·불일치 산출 | 관리자 |
| 5 | κ < 0.6 또는 일치율 < 0.8이면 해석 차이 정리 후 나머지 세트 채점 | 평가자 |
| 6 | 불일치 조정 | 조정자 |
| 7 | `merge`, `lock-scores` | 관리자 |

| 항목 | 내용 |
|---|---|
| 진입 조건 | 6B 완료, 평가자 지정, 노출 기록 |
| 호출 | 0 |
| 결과 저장 | `pilot1/rater_packet/`, `pilot1/scores/`, `pilot1/sealed/` |
| 주의 | 1차 평가자는 30세트 전체를 채점한다. `merge --primary`가 이 표를 기준으로 삼는다. |
| 중단 조건 | 평가자에게 `sealed/` 노출, 조건 추측 보고, 형식 오류 미해결 |

**재잠금 위험:** `merge`와 `lock-scores`는 다시 실행하면 기존 파일을 덮어쓴다. 잠금 후 채점을 고치고 다시 잠그는 것을 코드가 막지 않는다. `lock-scores`는 1회만 실행하고 `sealed/lock.json`의 해시를 별도로 기록한다.

### M1~M7 집계 시점

요청한 구성은 6C에서 M1~M7을 집계하는 것이다. 그러나 집계 명령 `report`는 M8까지 한 파일(`report.json`)에 쓰고 **기존 파일을 덮어쓰지 않으므로 사실상 1회만 실행할 수 있다.** 6C에서 실행하면 6D 뒤에 다시 실행할 때 파일 충돌로 실패한다.

**결정 (2026-11-03 사용자 승인): 6C는 잠금까지만 하고, M1~M7은 6D 끝의 `report`에서 M8과 함께 집계한다.** 코드를 바꾸지 않아도 되고, 조건별 결과를 본 뒤 6D 실행 여부를 바꿀 여지도 없앤다. 6C에서 꼭 집계하려면 `report`의 단계 분리 구현을 별도로 승인한다.

## Phase 6D: 후속 시뮬레이션 및 판정

핵심 4조건만 실행한다 (C0, C_full, A1, A2). A2s는 실행기가 거부한다.

| 항목 | 내용 |
|---|---|
| 진입 조건 | `lock-scores` 완료, 6B 실제 비용 정산, 판정기·시뮬레이터 해시 일치, 사용자 승인 |
| 예상 호출 | 시뮬레이터 24, `reassess` 24~48, `final_check` 48 = 96~120 |
| 예상 비용 | $1.03~2.88 (재시도 별도) |
| 결과 저장 | `pilot1/answers/`, `pilot1/downstream/`, `pilot1/attempts/` |
| 사후 작업 | `sim-audit`로 감사표 생성 → 평가자 작성 → `report` |
| 자동 중단 | API 오류 3회 연속, 고정 값 변경, 형식 실패 2회(해당 실행 실패 기록) |
| 수동 중단 | 판정기 변경 공지, 비용이 승인액 초과, 재개가 반복되어 비용이 불어남 |

**순서 검증:**

1. `report`와 `sim-audit`는 `sealed/lock.json`이 없거나 채점 파일이 바뀌면 조건 매핑을 열지 않는다. 테스트로 확인했다.
2. `report`는 잠금 통과 뒤에 조건 공개, 그 뒤에 정답을 읽는다.
3. 감사표에는 상세 설명이 들어간다. 이 시점부터 평가자는 Fact Sheet 노출자이므로 기록한다.

**재개 비용:** `final_check` 도중 멈추면 저장된 답변은 재사용하지만 그 실행의 판정 호출은 처음부터 다시 한다.

## 파일럿 결과 표현

결과는 개발 환자 2명의 탐색 결과이다. 환자를 합산하지 않고, 반복 실행을 독립 환자로 취급하지 않는다. 정답 노출자가 있으면 독립 정답 블라인드 평가로 표시하지 않는다.
