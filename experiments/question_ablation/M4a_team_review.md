# M4a 핵심 기준 정의 팀 검토 자료

**상태: M4a v2, 연구 담당자 확정 (2026-11-04, 정서현).** 선택 내용은 [M4a_approval_packet.md](M4a_approval_packet.md) 6절이 기준이다. 이 문서의 1·5·6절 일부(직접성 보존, v1 민감도, 원기준 완전 커버 보조값, H=0 잠금 거부, 표시되지 않은 H의 원기준 coverage 사용)는 확정안으로 대체되었다. 7절 변경 기록은 보존한다.

**배포 범위:** 1~3절은 전원이 볼 수 있다. **4~7절과 제안안 원문에는 가설과 조건 정보가 있으므로 사전 주석자와 평가자에게 주지 않는다.** 이들이 승인자이면 1~3절만 보고 정의를 승인한다.

출처: [04_annotation_guideline.md](04_annotation_guideline.md) 3절·4.2절, [04_question_rubric.md](04_question_rubric.md) M3·M4, `evaluation/scoring.py`의 `is_core`·`core_cov`·`set_metrics`.

## 1. 현재 정의 (v2)

### 1.1 무엇을 H로 보는가

| 항목 | 정의 |
|---|---|
| H | 확보 가능한 미확인 후보(Uv) 중 **조정 후 핵심성이 2점인 기준**. 직접성(확인 용이성)은 H에 반영하지 않는다. |
| 핵심성 2점 | 연구 대상 집단을 정의하는 핵심 조건(대상 질환·병기·필수 치료력), 또는 해당 시험 중재에 직접 관련된 핵심 안전 조건 |
| 핵심성 1점 | 대상·중재에 특화되지 않은 일반 건강·안전 요건 |
| 핵심성 0점 | 참여 운영·행정·절차 요건 |
| 안전 조건의 근거 | 기준 원문·시험 문서의 **명시적 설명**, 또는 주석 전에 고정한 **공통 근거 목록**(`safety_evidence.csv`). 약물명·계열이 언급됐다는 것만으로는 2점이 아니다. |
| 근거 부족 | 1점으로 낮추지 않고 **UNSURE**로 두어 조정한다. 조정 후에도 남으면 H가 아니며 건수와 사유를 보고한다. |
| 근거 기록 | 핵심성 2점에는 `centrality_evidence`가 필수이다 (`원문: <문구>` 또는 근거 ID). |
| 직접성 | 기록용으로 계속 주석한다. v1 정의를 민감도 분석으로 남기기 위해서이다. |
| `askable` | 핵심성과 따로 평가한다. 조정 후 UNSURE가 남으면 잠금이 거부된다. |

### 1.2 무엇을 커버로 보는가

| 항목 | 정의 |
|---|---|
| 핵심 부분 | 여러 하위 조건이 섞인 H 기준은 사전 주석에서 핵심 하위 조건(`core_part`)과 그 판정에 필요한 정보(`core_info`)를 표시한다. 원기준 전체가 핵심이면 표시하지 않는다. |
| `core_coverage` | 평가자가 핵심 부분이 표시된 연결에만 판단한다. FULL(핵심 부분 정보를 모두 요청), PARTIAL(일부를 실제로 요청), NONE(요청하지 않음, 비핵심 부분만 물은 경우 포함), UNSURE |
| PARTIAL의 문턱 | 관련 단어만 언급하거나 기록 보유 여부만 물은 것은 PARTIAL이 아니다. 답을 받았을 때 핵심 부분 판정에 쓸 정보가 나와야 한다. |
| 핵심 부분이 없는 H | 원기준 coverage를 쓴다. C3만 있는 PARTIAL(보유 여부만 확인)은 NONE으로 본다. |
| 원기준 coverage | 그대로 유지하며 M3에 쓴다. 핵심 부분만 FULL이라고 원기준을 FULL로 올리지 않는다. |
| 여러 질문에 나뉜 경우 | 한 연결이라도 FULL·PARTIAL이면 커버, FULL은 한 연결이 FULL일 때만. 질문 조각을 합쳐 FULL로 올리지 않는다. |

### 1.3 계산과 집계

| 값 | 계산 |
|---|---|
| M4a (주) | \|CoreSub ∩ H\| / \|H\| |
| 보조: 원기준 완전 커버 | \|Full ∩ CoreSub ∩ H\| / \|H\| (제안안 6절) |
| 보조: 핵심 부분 완전 커버 | \|CoreFull ∩ H\| / \|H\| (리뷰 문제 4) |
| 핵심 부분 UNSURE | 커버로 세지 않는다. 건수와, UNSURE를 커버로 본 상한값을 함께 보고한다. |
| 집계 단위 | 질문 5개 예산은 환자 단위(모든 시험 합산). 세트마다 계산하고 환자×조건별 3회 평균과 범위를 보고한다. 환자를 합산하지 않는다. |
| 빈 H | 지표는 값 없음. 현재 실행기는 환자별 H가 0개이면 잠금을 거부한다 (결정 9번). |
| 해석 범위 | 질문이 요청한 정보의 범위를 잰다. 답변 확보·판정 해결이 아니다. 첫 라운드만 본다. |

## 2. 예시

아래는 **설명을 위한 가상 기준**이며 실험 기준의 점수가 아니다.

### 2.1 핵심성

| 가상 기준 | 핵심성 | 근거 |
|---|---|---|
| 조직검사로 확인된 근침윤성 방광암 | 2 | 원문: 대상 질환과 병기를 정의 |
| 이전에 BCG 치료에 실패했어야 한다 | 2 | 원문: 대상 집단을 정하는 필수 치료력 |
| 시험약과 같은 계열 약물에 중증 이상반응 병력 | 2 | 원문이 시험 중재와의 안전 관련성을 명시 |
| 특정 약물 계열 사용 이력 (원문에 이유 없음, 근거 목록에도 없음) | UNSURE | 약물명 언급만으로 2점이 아니다. 근거가 부족하면 1점으로 낮추지 않고 조정 |
| eGFR 45 이상 | 1 | 일반 안전 요건. 결과지로 쉽게 확인되어도 H가 아니다 |
| 주 1회 방문이 가능해야 한다 | 0 | 운영 요건. H는 아니지만 M3에서 평가한다 |

### 2.2 핵심 부분과 커버 (제안안 5절)

원기준: "특정 질환으로 확진되었고 정기 방문이 가능해야 한다". 핵심 부분: "특정 질환으로 확진".

| 질문이 요청한 것 | core_coverage | M4a | 원기준 완전 커버 |
|---|---|---|---|
| 방문 가능 여부만 | NONE | 제외 | 제외 |
| 진단 정보 일부 | PARTIAL | 포함 | 제외 |
| 진단 정보 전부, 방문 여부는 안 물음 | FULL | 포함 | 제외 |
| 원기준 판정 정보 전부 | FULL | 포함 | 포함 |

## 3. 남은 쟁점

| 쟁점 | 내용 | 다음 단계 |
|---|---|---|
| 근거 목록의 범위와 작성자 | 어떤 자료(허가 정보, 시험 프로토콜 등)를 어느 버전으로 쓸지, 누가 작성할지 | 팀 결정 후 주석 전에 고정 |
| UNSURE 규모 | 근거가 부족한 안전 조건이 많으면 UNSURE가 늘어 H에서 빠질 수 있다 | 가상 사례 예비 주석과 근거 목록 작성 후 확인. UNSURE 건수와 사유를 보고 |
| 핵심 부분 구분 | 하위 조건 구분이 주석자마다 다를 수 있다 | 문구 차이는 조정 대상. 예비 주석에서 불일치 확인 |
| 필수 치료력의 범위 | 필수 선행 치료와 일반 치료력의 경계 | 예비 주석 후 예시 보충 |
| 평가자 부담 | 핵심 부분이 표시된 연결은 `core_coverage`를 하나 더 판단한다 | 표시된 H 기준에만 해당 |

## 4. 조작적 정의가 RQ2 결과에 주는 영향 (주석자·평가자 비공개)

RQ2는 A1과 C_full의 M4a 차이를 본다.

| 경로 | 설명 |
|---|---|
| 분모 크기 | 핵심성 2점만 쓰고 UNSURE를 빼면 v1보다 \|H\|가 줄 수 있다. 판단 규칙은 Δ가 반복 범위보다 커야 하므로 분모가 작을수록 판단 유보가 늘 수 있다. |
| 예산 포화 | H가 5개 질문으로 다룰 수 있는 양을 넘거나 크게 모자라면 두 조건의 차이가 줄 수 있다. |
| 정의와 프롬프트의 중첩 | v1은 직접성을 포함해 C_full의 우선순위 지시와 겹쳤을 수 있다. v2는 이 중첩을 줄인다. 어느 쪽이 유리한지는 실행 전 알 수 없으며, **정의 변경은 결과를 보기 전에 개념적 이유로 결정하였다** (제안안 10절). |
| 핵심 부분 커버 | 비핵심 부분만 묻는 질문은 더 이상 M4a에 들어가지 않는다. 어떤 조건이 그런 질문을 많이 하는지는 실행 전 알 수 없다. |
| 평가자 정보 | 채점표의 `core_part`로 평가자는 어떤 기준이 H인지 알 수 있다 (M6-A). 이 사실을 노출 기록에 남긴다. 모든 세트에 같게 들어간다는 이유로 편향이 없다고 주장하지 않는다. H 인지가 채점에 주는 영향은 측정하지 않았다. |
| 주석자 불일치 | `h_strict`와 `h_any`가 크게 다르면 H 집합 자체가 불안정하다. |

## 5. 사전 정의 분석 목록

**주 결론은 M4a(S0)로만 낸다.** 판단 규칙(방향 일치·방향 반대·판단 유보)은 바꾸지 않는다. v1의 S0~S5 목록은 쓰지 않는다 (제안안 9절).

| ID | 정의 | 묻는 것 | 코드 |
|---|---|---|---|
| S0 (주) | 핵심성 2점, 핵심 부분 커버 | v2 정의 | `M4a` |
| 보조 1 | H 원기준 전체 FULL | 원기준까지 충분히 물었는가 | `M4a_whole_full` |
| 보조 2 | H 핵심 부분 FULL | 핵심 부분을 완전히 물었는가 | `M4a_core_full` |
| 범위 | 핵심 부분 UNSURE를 커버로 본 상한 | 미해소 UNSURE의 영향 | `M4a_unsure_upper`, `n_H_core_unsure` |
| S1 | 한 주석자라도 핵심성 2점 | 주석자 불일치의 영향 | `M4a_any` |
| S2 | v1 정의 그대로 | 정의 변경의 영향 (같은 지표로 섞지 않음) | `M4a_v1` |
| 층화 | 핵심성 1점·0점 층의 M3b | 일반 안전·운영 요건을 덜 묻는가 | `M3b_c1`, `M3b_c0` |

**사전 규칙:**

1. 잠금 전에 이 목록을 고정한다. 결과를 본 뒤 정의를 추가하지 않는다.
2. 주 결론은 S0로만 낸다. 다른 값으로 주 판단을 바꾸지 않는다.
3. 모든 값을 \|H\|(`n_H`, `n_H_any`, `n_H_v1`)와 함께 환자별로 보고한다. 일부만 고르지 않는다.
4. S0의 판단이 S1·S2에서 유지되면 "정의에 안정적", 뒤집히거나 유보로 바뀌면 "정의 의존적"으로 표시한다.
5. \|H\| 하한(결정 7번)을 정하면 그보다 작을 때 값을 보고하되 판단은 유보한다.
6. 파일럿 결과로 정의를 바꾸더라도 같은 데이터로 재검증했다고 표현하지 않는다.
