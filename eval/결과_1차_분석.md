## 채점 오류였던 것 (모델 잘못 아님)

원본 출력을 열어 보니 일부 "틀림"은 평가 설계 문제였음. 코드와 정답을 고쳤고, 재실행이 필요함.

1. **Opus 4.8의 재평가 I1 "모름" 6건**: 근거에는 "모름 → 통과"라고 쓰고, verdict 칸에는 이전 판정(모름)을 넣음. "이전 → 이후로 표시하라"는 재평가 지시와 JSON 칸이 충돌한 것 → verdict에는 이후 판정만 넣으라는 문장 추가
2. **Opus 5.5·Sonnet 5.5의 재평가 세트 1 최종 판단 0/3**: 정답을 "적격"으로 잡았는데, 두 모델은 E3의 "조짐 유발 경련" 등 하위 조건이 확인 안 됐다고 E3를 "모름"으로 두고 최종 "정보 부족"을 냄. 판정끼리 일관되고 오히려 엄밀함 → 정답에 "정보 부족"도 인정
3. **Opus 4.8 시험 B 2회 실패**: 생각(thinking)이 길어져 출력 한도(16,000 토큰)에 걸림 → 한도 64,000 + 스트리밍으로 변경

## 진짜 발견

**1. 기본 판정은 모든 모델이 잘함**
시험 A, B, C는 Haiku의 A를 빼고 모든 모델이 100%. 웹에서 손으로 했던 결과가 반복 실행에서도 재현됨.

**2. 시험 D에서 예측했던 함정이 실제로 나옴: 규칙 3이 확실한 탈락을 막음**

| 모델 | E1 탈락 판정 | 최종 부적격 |
|---|---|---|
| Opus 4.8 | 3/3 | 3/3 (다만 I3 과잉 추론 탈락도 3/3, 웹과 같은 패턴) |
| Opus 5.5 | **0/3** | 0/3 |
| Sonnet 5.5 | 1/3 | 1/3 |
| Haiku 4.5 | 2/3 | 2/3 |

Opus 5.5는 세 번 모두 "조짐 편두통이 강하게 의심됨. 공식 진단 기록이 없어 모름. 진단이 확인되면 탈락"이라고 씀. 규칙 3("진단 기록이 없으면 모름")을 그대로 지킨 결과. 웹 실험(Opus 4.8)에서는 통과했지만, 모델을 바꾸면 무너짐
→ **규칙 후보 9("진단"을 묻는 기준과 "병력·증상"을 묻는 기준 구분)가 꼭 필요하다는 근거**

**3. 탈락 후 질문 여부는 모델마다, 실행마다 제각각**

| 모델 | 시험 C (나이 탈락) | 재평가 세트 2 (복용약 탈락) |
|---|---|---|
| Opus 4.8 | 1/3 지킴 | 3/3 |
| Opus 5.5 | 3/3 | **0/3** ("참고용" 질문) |
| Sonnet 5.5 | 2/3 | 1/3 |
| Haiku 4.5 | 3/3 | 3/3 |

큰 모델이라고 더 잘 지키는 게 아님. 규칙에 없는 행동은 모델 성향에 맡겨짐
→ **규칙 후보 7(탈락 확정 시 질문하지 않기)을 명시해야 함**

**4. Haiku 4.5는 "언급 없음 = 통과" 실수를 함**
시험 A에서 E1, E3를 3번 모두 "통과"로 판정. 근거도 "recurrent episodes이므로 만성 편두통이 아님이 명확"처럼 지어냄. 웹 실험의 규칙 없는 프롬프트 1과 같은 실수를, 규칙이 있는데도 함. 가장 싸지만 이 실수는 환자를 잘못 통과시킬 수 있어 위험

**5. 비용**
환자 1명 × 시험 1개 판정에 약 $0.02 (Haiku) ~ $0.1 (Opus). Sonnet 5.5가 일치율 99%에 Opus의 약 60% 비용이라 가장 효율적
